turing-smart-screen-python mathoudebine/turing-smart-screen-python

⭐ 2345 智能屏显示 源码 · Python 商业化 中

定位一批外接 USB 小屏的开源驱动与系统监视程序：把各家各写一套协议的 USB-C / UART 副屏统一到一层抽象上，画面内容由自己接管。

亮点覆盖十种尺寸的 Turing / TURZX 屏（2.1 到 12.3 英寸，UART 与 USB 两种协议都通），另加宣芳 3.5、UsbPCMonitor 3.5/5、奇叶智显 3.5、WeAct 0.96 与 3.5；抽象层顺带把机型专属功能也做了，比如背板 RGB 灯。两种用法：整套现成的系统监视器走主题，或者当成库由自己的 Python 代码直接控制屏幕。还没收到货也能开工，仓库带「模拟 LCD」模式，主题先在窗口里调好。明确不支持的也列了清单，波浪 USB-Monitor、GUITION、BeadaPanel 这类要改固件，作者直接写明做不到。

商业化中。屏幕是深圳几家厂商在卖，软件白给；能收钱的是主题定制、把副屏塞进机箱或工控面板的整机集成，以及给品牌客户改一套专属界面。

风险与坑163 个未关闭 issue，型号矩阵越铺越宽，问题也越积越多；外形相近的屏协议完全不同，买错型号就是一块砖；目前不支持视频与存储；GPL-3.0，闭源整机直接嵌进去会被传染。

⭐ 999 智能屏显示 固件 · 硬件套件 商业化 中

定位给 Gaggia 意式咖啡机加一块屏和一套控制板：锅炉温度、冲泡计时、蒸汽与热水都由屏上操作，原有机器不动，等于给老机器换一颗数字脑袋。

亮点做的是完整闭环：屏幕界面、控制板 PCB 与外壳文件放在 gaggimate/parts 仓（最近推送 2026-10-04），文档与采购清单一并迁到独立站点，另给了一份 WebSocket API 描述文件，第三方要接自建面板或自动化有据可依。安全逻辑写在固件里：系统失联或温度过高自动断电。项目挂了 SonarCloud 质量门，测试与代码异味可见；套件已在自家商店出售，等于硬件与软件都跑通了。

商业化中。改装套件是现成生意，客单价按整机零件算；软件与图纸开源，卖的是套件、装配与售后，另外还有给其他机型做适配的空间。

亮点建在 mjlab 与 MuJoCo Warp 上，同一套代码给两种坐标表示，任务号 SuperMimic-GenCoord-G1 与 SuperMimic-MaxCoord-G1，对应广义坐标与最大坐标两条路线；训练与回放各一条命令，走 uv 装环境，要并列 clone 姊妹仓 mjlab_research 才能跑。代码思路标了出处：ControlVAE、leggedrobotics 的世界模型、DreamerV3。仓库 2026-11-10 建立，两天内涨到 1300 星，跟着论文 arXiv 2610.28480 一起放出，说明这类「世界模型训人形」的路子正在被快速接手。

商业化弱。研究代码，直接卖不了；值钱的是把这条流水线接进真机遥操作与动作库生产，省掉一大截数据采集与调参人力。

风险与坑没有 release，也没有预训练权重说明，复现要从头训；依赖姊妹仓，两边版本错开就报错；只给 Unitree G1 一个机型；训练吃显存，单卡跑不了大动作库。

InstantTrack Huy-Quang-Dao/instantTrack

⭐ 196 具身 源码 · 训练代码 商业化 弱

定位把 SuperMimic 那条路线重做成能在几分钟内训完的版本：Unitree G1 的全身动作追踪，40 条 LAFAN1 动作、单张 RTX 5090，第一个检查点就达标。

亮点数字给得很实：2.45 小时动作、归一化回报 0.82、40 条片段 0 失败，耗时 3 分钟；作者自己在同一套仿真与评测下复现的 SuperMimic 要 1.50 小时，加上策略 EMA 也还要 0.55 小时，等于十倍以上的差距。v1.4 把更多计算挪到独立 CUDA 流上，每秒迭代从 10.28 提到 11.87；接触时脚滑 6.15 cm/s，参考动作本身是 10.2。v1.3 吸收了一个下游派生项目 BlinkMimic 的改动；作者另在做一个 InstantGMT，把这套训练思路用于 VR 遥操作动作库，一个策略覆盖整库。

商业化弱。单人研究项目，能变现的是把训练时间从小时级压到分钟级之后，动作库可以按天迭代，这项能力落在整机厂或遥操作运营方手里。

风险与坑作者自己标注 v1.4 的时间增益统计上不显著（p=0.10），可确认的是迭代速率；对比基准是自家复现的 SuperMimic，不是官方实现；只在 RTX 5090 与 mjlab 上测过；1 个未关闭 issue，外部验证几乎为零。

Alkove alkove-ai/alkove

⭐ 76 服务端配套 源码 · SDK + 模型权重 商业化 中

定位端侧语音前端一整套：语音隔离、唤醒词、语音活动检测、声纹，五个模型跑在设备本地，浏览器、Python、Android、iOS 都能调，无服务器、无密钥、无遥测。

亮点体积是真小：五个模型加起来不到 8MB，Focus 1.1MB，引擎 141KB（brotli 压缩后），自研 Rust 引擎。唤醒词支持任意词，七种语言直接输入，不用录音训练，指标是每小时一次误报下 80% 召回；near 模式不靠声纹，按音量把房间里远处的人声与别的设备播放挡在外面；Cue 做轮次起止，在音乐背景下误触发比 Silero VAD 少四倍。效果数据带数据集与协议放在 bench 目录：头戴麦会议录音里，他人语音进入转写的词从每分钟 17 个降到 0.5，普通降噪器还放过 19 个以上。插件已接 LiveKit Agents、Pipecat，以及 Home Assistant 的 ESPHome 与 Wyoming 两套协议。

商业化中。代码与权重都是 Apache-2.0，端侧白给；能收钱的是给终端厂商做定制唤醒词与多人场景调优，以及托管版的服务与支持。

风险与坑0 个未关闭 issue，说明还没有外部用户真跑过；80% 召回对消费级产品偏低，误唤醒与漏唤醒要按自家场景重测；模型与权重只有一家在维护；接到 Home Assistant 之后仍要自己做服务端编排，这一层它不管。

定位把俄区 Yandex Station 系列智能音箱改成 Home Assistant 的本地语音卫星：原厂栈 maind 被换成一个小的原生守护进程，按 ESPHome Native API 与 HA 通信，在 HA 里就是一台普通 ESPHome 设备。

亮点原厂硬件基本全用上，且靠的是设备自带资源：唤醒词模型与多麦回声消除还是原厂那套（按机型 2 到 4 个麦克风，含自家喇叭声音的扣除）；「停止」「大声点」这类本地命令在音箱上直接执行，不经 HA；几台同时听到时由听得最响的那台回应；LED 环或面板、时钟、按键、麦克风硬开关、光照传感器都映射成了 HA 实体；Midi 机型的 Zigbee 模块还能当 Zigbee2MQTT 与 ZHA 的协调器或中继。播放侧同时是 Music Assistant 的 Sendspin 原生播放器，断流有三次重连。私有库不在仓库里分发，运行时从设备自身加载。

商业化弱。AGPL-3.0，且依赖俄区存量机型；可变现的是这批旧音箱批量改造的集成与运维服务。
