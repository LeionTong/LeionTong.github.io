LANovo ygelfand/LANovo

⭐ 28 语音终端 固件 商业化 弱

定位把联想 Smart Display 10/8/7、JBL Link View 与 ThinkSmart View 刷成 Home Assistant 的本地语音卫星，沿用机身原有的麦克风、扬声器、摄像头与传感器，HA 通过 ESPHome 原生协议自动发现设备。

亮点AGPL-3.0，2026-10-02 创建、2026-10-28 最近推送，最新版本 0.0.6（2026-10-28），28 星。主机侧是一个 Go 写的 CLI，负责检查设备、安装、配 Wi-Fi 与配对，刷机后设备不再连 Google 的服务。设备表覆盖五个型号，姊妹项目 EchoLocal 再把 Echo Dot 二代与 Echo Show 5/8 接进来。界面侧给了 LCARS、锦鲤池、合成波一类动态音频可视化，也能当电子相框、荧光管时钟、带实体按键的报警面板与照片墙用。

商业化这几款屏是 Google 停止支持后流到二手市场的存量货，硬件不再生产，能做的生意是回收再制造、批量刷机与上门安装，按台收服务费；AGPL-3.0 对想闭源出货的整机厂不友好，愿意开源的一方才能接。

风险与坑刷机前必须先解 AVB 引导锁、换刷 Android 8.1 调试固件，步骤在 XDA 的两个长帖里，操作失误会把设备刷死；只支持表内这几个已停产型号，ThinkSmart View 的做法还要到社区里问；整套体验绑定 Home Assistant，脱离 HA 这套固件没有独立价值。

FrankenSonos Dicklesworthstone/frankensonos

⭐ 109 语音终端 源码 商业化 中

定位Rust 写的 Sonos 音箱控制器与常驻服务，一个二进制同时提供命令行、HTTP 接口与 MCP 接口，家里已有的 S1 与 S2 两代音箱照旧用，只在本地网络里指挥它们。

亮点2026-10-06 创建、2026-10-31 最近推送，109 星。协议层自己实现 SSDP 发现、UPnP-SOAP 控制与 GENA 事件订阅，不依赖官方云；挂上 Tailscale 后可以在任何网络里远程操作整套房子。作者用 fsonos-sim 搭了一套虚拟家庭做端到端测试，S1 与 S2 各一套在回环上跑真实报文。接口面向智能体设计，命令行、HTTP、MCP 三条路都能接自动化。

商业化Sonos 存量设备体量大，绕开官方账号做本地控制是长期需求，适合做家庭自动化集成、酒店与门店的多区音频运维；许可为 MIT 加一条针对 OpenAI 与 Anthropic 的附加条款，做商业集成前要逐条读正文再定报价模型。

风险与坑还在 0.1.0 之前，没有正式 release，接口会变；Rust 2024 nightly 编译，工具链跟不上的机器直接编不过；只负责发现与控制播放，语音识别、唤醒词与对话都在它之外；附加条款一旦与自家业务冲突，整套方案就要换许可版本，这一点必须先谈清楚。

Apple Watch Companion LordixDemon/apple_watch_connector

⭐ 667 穿戴 应用 商业化 中

定位把 Apple Watch 从 iPhone 独占里放出来：自己实现发现、配对、激活、重连、偏好交换与原生表盘管理，让手表能连安卓、Linux 与 Windows，四个平台共用一套 Flutter 伴侣端。

亮点2026-10-13 最近推送，667 星、62 个 fork，是本期热度最高的一条。安卓侧以 Magisk 模块交付（0.2.427），接管手机侧连接与密钥，支持摄像头配对；Linux 与 Windows 用 Rust 桌面后端加原生 HCI 通道，按手表屏幕上的六位数字配对。作者在实机上验证过新配对、激活与同配对加密重连，桌面端的应用服务覆盖仍是部分完成。仓库里把研究探针、协议运行时与发布流程分开放，读起来像工程记录。

商业化把 Apple Watch 接到非苹果设备是多年没被满足的需求，安卓用户、双机用户与做桌面自动化的人都在等；可走企业设备管控、表盘分发与定制固件服务，按设备台数收年费的模式成立。

风险与坑仓库没有 LICENSE 文件，GitHub 识别为 NOASSERTION，商用授权必须先找作者书面确认；安卓侧依赖 Magisk 获取 root，普通用户装不上，量产机型没有这条路；只在 watchOS 26.2（23S303）上测过，系统一升级协议就可能失效；桌面端功能仍是部分完成，不能当作成品交付。

chums lcoutodemos/chums

⭐ 288 穿戴 应用 商业化 弱

定位把 Mac 上已经在跑的 Claude Code 与 Codex 搬到 Apple Watch 和 iPhone：按住表盘说话、松手发送，每个编码智能体在手表上是一个会表演动作的角色，跑起来的状态直接演给人看。

亮点Apache-2.0，2026-10-13 创建，288 星、38 个 fork。设计上不引入新模型、不卖新订阅，手表和手机通过 Tailscale 连回自己 Mac 上的 hub，没有第三方账号，智能体按角色从手表或手机切换。作者把安装写成一段提示词交给编码智能体执行，人手只负责登录、插线与打开开发者模式。仓库里有架构、角色与排错三份文档，形态上像把终端会话塞进表盘。

商业化自用工具，条件卡得很死：要 watchOS 26 与 iOS 26 的手表手机、Apple silicon 的 Mac 与 Xcode 26，还得自己签名安装，规模化的余地很小；它的价值在于把「手表当智能体终端」这个形态跑通，给做穿戴入口的团队当参考实现。

风险与坑只能从源码构建，首次配置 20 到 30 分钟，还要额外等 Xcode 处理手表、等 Funnel 地址在公网 DNS 生效；创建后 18 天没有新推送，节奏偏慢；无 release，无 App Store 分发，系统升级后要跟着改。

Watch Unlock Windows whyy1/watch-unlock-windows

⭐ 64 穿戴 应用 商业化 弱

定位用 Apple Watch 解锁 Windows：戴着表走开再走回来，锁屏自己解开，补上 Windows 动态锁只负责锁、不负责解的缺口。

亮点AGPL-3.0，Rust 写，最新版本 v0.2.9（2026-10-28），2026-10-31 仍在推送，64 星。作者在 Windows 11 Pro 加 Apple Watch 上实测过：一键绑定、走远返回约 0.17 秒解锁、关掉无感解锁时等待键鼠操作、原地锁屏不解锁。密钥处理写得比较克制：账户密码、每块手表的 IRK 与通知密钥分别用 DPAPI 按当前账户加密，存在本地目录；只有请求来自系统登录界面且自身跑在只有管理员可写的 Program Files 下，才会把密码交给 Windows 校验。中文文档把局限逐条列在了前面。

商业化单人维护的小工具，正面对手是免费的 Windows Hello 与系统动态锁，很难单独卖钱；可收费的部分在企业侧的设备信任策略与批量部署咨询，前提是先把重放与中继的窟窿补上。

风险与坑读不到手表是否戴着、是否解锁，四种状态下蓝牙广播内容完全相同，表没戴在身上、被别人拿着走近同样会触发解锁；判断只依据 IRK 与信号强度，防不住广播重放与中继，墙体与人体遮挡会让 RSSI 误判；不支持远程桌面会话，安装包没有代码签名，会被 SmartScreen 拦；AGPL-3.0 与闭源分发冲突。

定位三轴桌面机械臂的整套资料：22 个 SolidWorks 零件、3 个装配体、4 个 STEP，加 Arduino UNO 固件与 Python/PySide6 上位机，从建模到控制一条链给全。

亮点MIT（作者自有模型与代码），2026-10-27 创建并推送，31 星。控制侧 X/Y/Z 三轴步进独立运行、各自计数与显示进度，可以并行启动与单独停止，另有 D12/D13 两个 0 到 180 度的舵机滑块；2026-10-22 把界面改成三轴并排，不必切换控制轴，改的是上位机，协议 v3 固件不用重烧。不依赖 GRBL 与 AccelStepper，串口协议与接线说明都写在仓库里。

商业化图纸型项目，卖点在课程与套件，单卖模型卖不出价格；要变成商品，缺的是实机验收记录与自包含的整机模型，眼下更适合当教学材料与结构设计参考。

风险与坑总装配体 STEP 引用了仓库里没有的外部零件，作者自己说明这不是自包含的整机文件，直接下单加工会缺件；软件只过了模拟测试与固件编译，实机运动与装配完整性没有验收；没有同步插补，做不了连续轨迹，只能单轴或简单并行。

UWB 桌面定位 HetaoLu-Creater/uwb-localisation

⭐ 97 桌面机器人 源码 商业化 弱

定位在桌面上给旋转小车做实时定位：三个 Ai-Thinker BU03 基站加一个标签测距，Python 主机程序把距离解成平面坐标，在浏览器里实时画出来。

亮点MIT，2026-10-25 最近推送，97 星。处理链分五段：逐基站测距滤波与标定、加权位置解算、Kalman 跟踪、平滑与显示控制，每一步都能单独跑。每次实时运行都存档，可以按原始测量时刻回放再处理。仓库里带 0.6 米与 1 米两种布局的静止与手持录制数据、复现脚本与测试，作者写明短距原始测距本身有偏、偶尔中断，方法是在录下来的数据上一步步磨出来的，结论可以复算。

商业化定位模组是通用件，值钱的是这套把短距偏差与丢包处理成可用坐标的滤波链，可做桌面机器人比赛的裁判与回放系统、教学套件，或给玩具厂做多点位互动。

风险与坑验证场地只有 0.6 米与 1 米，放大到房间尺度要重新标定，参数不能直接搬；UWB 遇金属与人体遮挡会跳点，基站摆位要提前设计；只有定位没有控制，接到机器人上得自己写闭环，且仓库是毕设形态，后续维护没有承诺。
