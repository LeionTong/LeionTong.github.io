定位自托管的命令行智能体，读失败的 CI 运行，追到原因并把修复作为 PR 提交。

痛点按 token、按调用、按席位混合定价的产品，用量散在日志里，出账要拼三张表，改一次价格要改一遍代码。

TrnRT RunanywhereAI/trnrt

⭐ 1,658 · 建仓 24 天，全部落在近 30 天窗口内 Python · Apache-2.0 最近提交 2026-11-08 · v0.1.0（11-08）

定位AWS Trainium2 上的开源推理引擎，用 NKI 巨核把 GLM-5.3-Flash 服成 OpenAI 兼容接口。

痛点Trainium 单价便宜，却没有 llama.cpp 或 vLLM 那样的开箱推理栈，自己写 NKI 核的门槛挡掉了多数团队。

付费Apache-2.0 免费；RunAnywhere 靠 Wally 云端按预付费额度卖 token，引擎开源用来证明单位算力能出多少吞吐。付钱的是手里压着 Trainium 承诺用量、要把每 token 成本打下去的公司。

规模化单台 trn2.48xlarge 起服务，Docker 构建，前缀缓存跨设备与主机内存；目前只支持一个模型，仓库说后续补。

边际中 · 软件免费，交付要绑 trn2 实例与 Neuron SDK，硬件账算在客户头上。

验证有实例时按仓库 README 构建镜像，再编模型形状（本机跑不动）：

git clone https://github.com/RunanywhereAI/trnrt && cd trnrt
trnrt compile shapes zai-org/GLM-5.3-Flash --out /data/trnrt
trnrt compile decisions --model zai-org/GLM-5.3-Flash --out /data/trnrt
风险第一步就要八卡 Trainium2 实例，30 分钟内本机验证不了；单模型、v0.1.0，11-08 之后默认分支没有新提交。

今日首选

OpenMeter（openmeterio/openmeter）。五条里它的付费路径最清楚，商业版已经进了 Kong 的云服务，开源版还是同一套代码。按用量计价的产品迟早要自己算准每一个 token、每一次调用，而这件事用 Docker Compose 十分钟就能看到结果。

组合观察

智能体把每个人的产出放大之后，配套的追责与记账工具还停在个人脚本的水平：CI 失败要人来归因，成果没人签收，用量散在日志里，算力账单按实例走。开源项目在这里挣钱的方式也一致——代码免费，钱落在托管服务、私有部署和算力转售上；硬件绑定越深的条目，验证门槛越高，客户也越少。
