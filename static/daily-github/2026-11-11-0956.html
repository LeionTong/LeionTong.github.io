痛点日志散在 rosbag、MCAP 与各家私有格式里，调试靠人拖时间轴，团队最后都自建一套回放平台。

付费开源核心免费，商业面是 Rerun Hub 这个对象存储上的数据目录，目前私有预览、面向设计伙伴；公司已融 1,700 万美元。买方省掉的是 Foxglove 这类按席位订阅与自研平台的人力。

边际低 · 只发库与查看器，渲染与解码在客户端完成。

验证装 SDK 后两行记录点云与位姿，查看器直接起：

pip install rerun-sdk
python -c "import rerun as rr; rr.init('t'); rr.connect(); rr.log('p', rr.Points3D([[0,0,0]]))"
rerun
风险Hub 还在私有预览、没有公开价格，收入结构验证不了；可视化这一格 Foxglove 已占住团队工作流；ROS 用户习惯 RViz，迁移要重写工具；Apache 与 MIT 双许可意味着不留商业护城河，护城河全靠 Hub。

Newton newton-physics/newton

⭐ 5,939 · 近 30 天 +381 Python · Apache-2.0 最近提交 11-10 · v1.7.0 于 10-14

定位跑在 Warp 上的 GPU 物理引擎，以 MuJoCo Warp 为主后端，求解器可插拔，面向机器人学习与仿真研究。

痛点CPU 仿真一天才攒出一批 rollout，接触密集的抓取与行走更慢；商用仿真平台按节点授权，扩容先撞预算。

付费Linux Foundation 项目，代码 Apache-2.0、文档 CC-BY-4.0，引擎本身不收钱；收入落在上游 NVIDIA 的卡与 Omniverse 订阅，以及给研究所搭仿真集群的集成商。

规模化Isaac Lab 已接进来，同一套 API 覆盖刚体、软体与多物理，可微性直接进训练循环；跨实验室、跨机型通用。

边际低 · 纯软件分发，算力由用户自己的卡承担。

验证NVIDIA 显卡机器上装 examples 跑一个刚体例程：

pip install "newton[examples]"
python -m newton.examples --describe robot_omniwheel
python -m newton.examples robot_omniwheel
风险只吃 NVIDIA 显卡，Windows 要过 WSL；十月还在删改接口，v1.x 小版本就能打断现有代码；引擎免费，谁也没法靠它单独收费，收益要挂在硬件或服务上；与 Genesis 这类多后端引擎正面撞。

Cerulion cerulion-inc/cerulion

⭐ 102 · 近 30 天增量未获取到 Rust · AGPL-3.0 最近提交 11-11 · v1.0.0 于 09-21

定位机器人节点运行时，按节点图调度、走 iceoryx2 零拷贝共享内存，运行全程录制，回放同一段能对着新代码重跑并给退出码。

痛点真机时间最贵，却大半耗在 ROS 2 的 executor 与 DDS 调参上；急停路径一被阻塞就得整机复位，故障没法变成测试用例。

付费开源运行时 AGPL，公司是 YC S24、两位 MIT 博士创立，商业面是 Studio 图形工具与远程接入，按团队授权；客户是拿真机做交付的机器人公司。

规模化一套 CLI 跨 Linux 与 macOS，带 ROS 2 Jazzy、Lyrical 的 rmw 桥，现有节点能逐个搬，不必一次重写。

边际低 · 发二进制与授权文件，录制数据留在客户自己的机器上。

验证装 CLI 后跑 README 里的激光安全控制器例程，看录制与判定：

curl -fsSL https://raw.githubusercontent.com/cerulion-inc/cerulion/main/tools/scripts/install.sh | sh
. "$HOME/.cerulion/env" && cerulion login
cerulion run examples/safety_controller
风险AGPL 对往闭源产品里嵌的团队是硬门槛，很多机器人公司会因此只试用不采购；节点必须用与 CLI 同一个 rustc 编译，工具链锁得死；102 星，生态薄，离开官方例子就要自己趟。

Robotocore robotocore/robotocore

⭐ 334 · 近 30 天增量未获取到 Rust · MIT 最近提交 11-11 · 发行版 v2026.11.11

定位本机跑一份 AWS 数字孪生，160 个服务、96% 的操作有实现，任意 SDK、CLI 或智能体照常调用，端口 4566 与 LocalStack 相同。

痛点LocalStack 社区版收缩后，CI 里跑云集成测试要么买 45 美元每席每月的 Base 档，要么连真云烧账户；团队规模一涨，席位费按人头线性走。

付费无注册、无遥测、MIT 免费，省下的就是席位费；可收钱的位置是企业支持、镜像托管与合规审计包。

规模化一个容器跨语言跨团队通用，多账号、多区域、IaC 都能本地跑，替换只改端点地址；云原生团队的需求高度同质。

边际低 · 单容器，全部在用户机器上跑。

验证起容器后用标准 AWS CLI 打过去：

docker run -d -p 4566:4566 jackdanger/robotocore:latest
aws --endpoint-url http://localhost:4566 s3 mb s3://demo
风险一个人全用智能体写出来的，160 个服务的行为保真度只能逐个核对；没有公司主体，出了问题没有合同可依；按日期滚动发版，回归面铺得很大；LocalStack 掉过的坑，它同样会掉。

Calibrex rsasaki0109/Calibrex

⭐ 60 · 近 30 天增量未获取到 Python · Apache-2.0 alpha 最近提交 11-11 · v0.6.4 于 11-11

定位拿一段 rosbag 判断车上传感器标定还准不准，对每个轴给通过与超差结论，也能反过来从数据里估一份外参。

痛点外参漂移靠路测与肉眼发现，激光点云歪到柱子上才有人查；量产车与车队没有下线复检的手段，标定文件几个月没人碰。

付费车队运维与量产下线检验，按车按次出报告；开源免费，收钱位置是带判定阈值的检测服务与报告归档。

规模化一条命令吃标准 bag，结论出 JSON 与 HTML，能直接进流水线；覆盖 LiDAR、IMU、相机、GNSS、车辆五类配对，跨车型通用。

边际低 · 纯 Python，不依赖云与专有硬件。

验证装 wheel 后先让工具说这段数据能查哪几对：

python -m pip install "https://github.com/rsasaki0109/Calibrex/releases/download/v0.6.4/calibrex-0.6.4-py3-none-any.whl"
calibrex check my_bag/ --plan
风险alpha、60 星、单人维护，判错一次就会误报好车或漏放坏车；公开验证只到 KITTI、NTU VIRAL、Hilti 三个数据集；平移量 xyz 不判定，只判角度，装车位置错了它看不出来。

组合观察
