pdf-inspector firecrawl/pdf-inspector

⭐ 18,822 近 30 天 +9,431 Rust MIT v1.15.0 · 2026-08-17 主流

定位Rust 写的 PDF 分类与抽取库，先判断要不要 OCR，再决定怎么抽。

痛点文档管线默认对所有 PDF 上 OCR，官方口径约 54% 的 PDF 其实不需要，这笔钱纯属浪费。

谁付钱RAG、合同审查、票据与财报处理团队；省下的是 OCR 服务调用费。库本身 MIT 免费，可变现的是集成部署与托管管线。

规模化凡有 PDF 入库环节的行业都通用，Rust / Python / Node / WASM 四种 binding，接入完全标准化。

边际成本低 —— 纯客户端库，无服务端、无 GPU，客户自带算力。

验证≤30 分钟：

pip install pdf-inspector
import pdf_inspector
r = pdf_inspector.process_pdf("任意一份.pdf")
print(r.pdf_type, r.markdown[:200])   # 用真实合同/财报跑一次，看分类是否命中

官方 Quick start → github.com/firecrawl/pdf-inspector#quick-start

风险212 个 open issue 偏高；benchmark 由 Firecrawl 自行跑分（opendataloader-bench 语料 200 份 PDF），需在自己语料上复测；它只解决「分类 + 抽取 + 选择性 OCR」，复杂版面还原仍要兜底方案。

celld denoland/celld

⭐ 4,491 近 30 天 +4,433 Rust Apache-2.0 v0.4.0 · 2026-08-28 主流

定位把 Cloudflare Workers 与 Durable Objects 搬到自己机器上跑的自托管守护进程。

痛点Durable Objects 这套有状态模型好用，但强绑 Cloudflare，迁移成本几乎等于重写。

谁付钱被 CF 绑定、或受数据出境约束的团队；Deno 官方走托管变现，第三方可做自托管运维服务与迁移交付。

规模化状态型边缘应用是通用需求，客户群等于「所有在用 Durable Objects 的人」，可打包成标准托管套餐。

边际成本中 —— 纯软件，但托管形态需按 cell 提供机器与对象存储，成本随客户量走。

验证≤30 分钟：

curl -fsSL https://celld.dev/install.sh | sh
celld --help

备一个 S3 兼容桶，按 celld.dev/docs 起单节点，部署一个最小 Wrangler 项目，看 cell 是否被正确持有。

风险v0.4.0 未到 1.0，ownership 与 LTX 复制协议复杂，排障门槛高；需 esbuild 与对象存储；单节点写入要等桶确认，性能明显弱于多节点。

Jarvis Registry ascending-llc/jarvis-registry

⭐ 2,771 近 30 天 +未获取到 Python Apache-2.0 cli-v0.3.1 · 2026-09-05 小众

定位企业级 MCP / A2A 网关，把 Agent 接内部工具这件事统一到带身份、权限与审计的单一入口。

痛点Agent 接内部系统现在各接各的，凭据散落、谁调了什么说不清，安全与合规两头发堵。

谁付钱有合规要求的政企与金融；对标 Kong AI Gateway、Solo.io Agent Gateway，走企业授权与托管订阅。

规模化企业 AI 治理是跨行业刚需，交付物是一套 Docker 栈加 IdP 对接，可标准化复制。

边际成本低 —— 纯软件自托管，Apache-2.0 可闭源二次分发，无重人力驻场。

git clone https://github.com/ascending-llc/jarvis-registry.git && cd jarvis-registry
cp .env.example .env && docker compose --profile full up -d
# 打开 http://localhost:80

Magnitude magnitudedev/magnitude

⭐ 2,548 今日 +391 TypeScript Apache-2.0 cli@0.0.11 · 2026-09-02 小众

定位本地推理服务器，按你机器的配置挑最优模型，接到你已经在用的编码 Agent 上。

痛点Claude Code、Codex 这类 Agent 全天跑，token 账单和代码出网是两道硬门槛。

谁付钱研发团队与有代码不出网要求的行业；省的是云端 token 费，可变现的是团队版网关订阅与硬件选型交付。

规模化用 AI 编码 Agent 的团队即客户，跨行业通用；局限是依赖客户端机器有足够内存与算力。

边际成本中 —— 自托管复制零成本，但一旦做托管，每个客户要占一套 GPU 资源，成本随客户线性上升。

验证≤30 分钟：

npm i -g @magnitudedev/cli
magnitude setup     # 交互式；建议先只跑 profiling 看推荐模型，别急着下权重

风险版本仍 0.0.x、仓库仅 3 个月，未到生产可用；Windows 只支持 WSL；首次下载模型权重可能远超 30 分钟；本地模型在复杂重构任务上质量仍明显弱于前沿闭源模型，必须留云端兜底。

Shippie mattzcarey/shippie

⭐ 2,492 近 30 天 +未获取到 TypeScript MIT main 近 30 天 0 提交 小众

定位跑在 CI 里的代码评审 Agent，读 diff、用真工具翻代码库、只提人会提的问题。

痛点CodeRabbit、Greptile 这类 AI 评审按席位月费收，团队规模一上来就是固定支出。

谁付钱任何有 PR 流程的研发团队；MIT 允许闭源售卖或做托管，成本差可精确算到每人每月。

规模化PR 评审是全行业通用动作，GitHub Action 一行接入，零定制、零实施。

边际成本低 —— 纯软件加 Action，无服务端，唯一成本是调用方自付的 LLM token。

验证≤30 分钟：

git add .           # 先把改动暂存
npx shippie review  # 结果写入 .shippie/review/local_*.md

接 CI 用 npx shippie init 生成 workflow，配 ANTHROPIC_API_KEY 即可在 PR 上出评论。

风险⚠️ main 分支近 30 天 0 次提交（最后提交 2026-07-02，约两个月停滞），release 停在 v0.21.2（2026-06-23），成熟度是今日五条最弱一环；好处是 MIT 且已有 243 个 fork，若确认长期停更，接过来做商业版的法务与工程成本都很低。

一、今日首选

firecrawl/pdf-inspector。它是今日唯一五维无短板的标的：MIT、纯客户端库、一条 pip install 即可验证，且省下的钱能被精确算出来——约 54% 的 PDF 根本不需要 OCR。替代账越具体，成交阻力越小。

二、组合观察

今日五条里有四条在做同一件事：把按次或按席位计费的外部依赖，换成自有可控的软件栈——OCR 调用（pdf-inspector）、Durable Objects（celld）、MCP 接入（Jarvis Registry）、Agent 推理（Magnitude）；Shippie 则是用 Agent 直接顶掉按席位收费的 SaaS。

信号很清楚：开源商业化的主战场已从「模型能力」彻底转向「账单项替换」——谁能把客户现有账本上的某一行换成自有软件，谁就拿到定价权。

第二层信号：五条全部是 MIT 或 Apache-2.0，License 不再是商业化障碍，竞争完全落在谁先把替代账算清楚。
