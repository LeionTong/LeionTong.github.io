LiteRT-LM google-ai-edge/LiteRT-LM

⭐ 6,860 · 近 30 天增量未获取到 C++ · Apache-2.0 最近提交 11-12 · v0.19.1 于 11-05

定位Google 的端侧大模型运行时，跑在 LiteRT 上，一套引擎配 C++、Kotlin、Swift、Python、JavaScript 接口，覆盖 Android、iOS、浏览器、桌面与树莓派。

痛点应用要在自己设备上出模型，得挨个对接 GPU 与各家 NPU 驱动；走云端 API 则按 token 付费，离线与数据不出机的场景又必须留在本地。

付费引擎免费，省下的是云推理账单。Chrome、Chromebook Plus、Pixel Watch 已经在用，工程路径被自家产品验过；对应用方的价值是同一份模型代码跨端复用，不必为每个平台重写。

规模化六种语言接口、五个平台，模型侧覆盖 Gemma、Llama、Phi-4、Qwen，带视觉与音频输入，函数调用可用于智能体流程。

边际低 · 只发库、CLI 与 Web SDK，算力在用户设备上。

验证装 CLI 后一条命令跑 Gemma 4，模型从 Hugging Face 拉：

uv tool install litert-lm
litert-lm run \
  --from-huggingface-repo=litert-community/gemma-4-E4B-it-litert-lm \
  gemma-4-E4B-it.litertlm --backend=gpu \
  --prompt="What is the capital of France?"
风险756 个未结 issue，NPU 后端仍按芯片厂商分别适配，换机型要重测；发版节奏由 Google 定，外部改动难进主线；Swift 与 JS 接口还是预览状态；近 30 天 star 增速平缓，热度靠发布会推。

vLLM-Omni vllm-project/vllm-omni

⭐ 7,705 · 近 30 天 +438 Python · Apache-2.0 最近提交 11-12 · v0.33.0rc1 于 11-04

定位在 vLLM 之上加一层统一伺服，把文本、图像、音频、视频与动作模型的推理收进同一个 OpenAI 兼容服务端，含全双工实时语音与机器人策略伺服。

痛点一个产品同时要出 TTS、扩散出图、Omni 对话与 VLA 策略时，团队得维护三套推理栈；用闭源多模态 API 则按秒计费，长尾与峰值流量最贵。

付费自建推理的模型公司与云厂，省下的是按秒计费的多模态 API 与多栈运维人力。已有技术报告、部署配方站与 nightly 镜像，企业侧可直接照着上线。

规模化版本线与上游 vLLM 对齐，CUDA、ROCm、XPU、NPU 都有路径，Ray 多机可选；模型清单随上游发布滚动，含 π0.5、GR00T 这类策略模型。

边际低 · 纯软件，卡由使用方出。

验证起一个文生图服务端再打一次接口：

vllm serve Tongyi-MAI/Z-Image-Turbo --omni --port 8091
curl -s http://localhost:8091/v1/images/generations \
  -H "Content-Type: application/json" \
  -d '{"prompt":"a cup of coffee","size":"1024x1024","response_format":"b64_json"}'
风险1,926 个未结 issue；主次版本必须与 vLLM 严格对齐，错位直接报错；只支持 Linux，源码装要 CUDA 13 与指定 torch；rc 版本线密集，接口与配方还在改。

Kapitsa nace-ai/kapitsa

⭐ 741 · 近 30 天 +741 C++ · Apache-2.0 建仓 10-16 最近提交 11-12 · v0.2.35-rc1 于 11-11

定位Apple silicon 上的推理引擎，按 Qwen3.6 35B-A3B 这类 MoE 调优，把 opencode、Claude Code、Codex、aider 直接引到本机模型，同时开 OpenAI 与 Anthropic 两套接口。

痛点订阅制编码工具按人按月收钱，代码却要出本机；MLX 与 llama.cpp 在 Mac 上的解码速度与首字延迟撑不住交互式编码，重启后缓存还得重算。

付费省下的是编码订阅与 API 账单，引擎本身没有收费面。作者一个人的项目，商业路径还没铺，变现要靠后续的托管或支持。

规模化只吃 Apple silicon，M1 以上；一条 CLI 接管七种编码智能体；多台 Mac 能拼一个装不下的模型，覆盖范围随 Mac 保有量走。

边际低 · 纯软件分发，算力在用户自己的机器上。

验证装完直接起一个编码智能体：

brew install nace-ai/tap/kapitsa
kapitsa opencode --model 35b
风险建仓不到一个月，v0.2.x 还是 rc；速度数据全部来自作者自测，没有第三方复现；只支持 macOS，Windows 与 Linux 用户用不上；180B 模型靠 SSD 流式加载，体验随磁盘与内存抖动；单人维护，断更没有兜底。

Mosaico mosaico-labs/mosaico

⭐ 1,128 · 近 30 天增量未获取到 Python · Rust · Apache-2.0 最近提交 11-11 · v0.7.0 于 10-13

定位机器人传感器数据平台，把 rosbag、MCAP 与自定义传感器流写进带本体与 schema 快照的存储，按物理量做条件检索，只取需要的那段时间片。

痛点十小时日志里找两秒的异常要整文件扫一遍；格式一换，历史数据就读不动；多个进程同时写同一个存储会互相踩，最后都靠自研脚本糊住。

付费开源核心，官网直接约商务，团队三人来自 Ambarella 与 Magneti Marelli，已拿投资。省掉的是自建数据管道的人力与云端按量存储费，买方是数据量到 PB 级的机器人团队。

规模化一套 SDK 吃多种格式，服务端走 Arrow Flight，底层落在 S3、MinIO 或本地盘，可整机部署在客户机房或车上。

边际低 · 软件分发，存储与算力都在客户侧。

验证一条命令装起守护进程，SDK 连上 6726 端口推一条 IMU：

curl -fsSL https://get.mosaico.dev | sh
pip install mosaicolabs
风险只有 Python SDK；查询语义绑在自家本体上，迁出成本高，用起来也等于被锁定；56 个 issue、团队小；数据这一格与 Rerun、Foxglove 正面重叠；v0.x 阶段，接口还会变。

NeMo Gym NVIDIA-NeMo/Gym

⭐ 1,330 · 近 30 天增量未获取到 Python · Apache-2.0 最近提交 11-12 · v0.7.0 于 10-06

定位NVIDIA 的环境层，把数据集、智能体外壳、判分器与任务状态打包成可复跑的环境，同一套环境既做评测也做强化学习训练。

痛点智能体评测散在各人自写的脚本里，换团队就复现不了；评测迁到训练要重写一遍；上千并发与长跑任务一断就得从头再来。

付费库免费，商业面在 NVIDIA 的卡与 NeMo 企业套件。买方省掉的是 LangSmith、Braintrust 这类按席位与按次计费的评测订阅，以及自建评测平台的工程时间。

规模化环境跨框架复用，已接 vLLM、Verl、NeMo RL、Unsloth；带 OpenTelemetry 链路追踪；Slurm 超时与抢占后自动续跑，在 Nemotron 训练里用过。

边际低 · 纯软件，推理算力自备。

验证拉仓库建环境，写一份 env.yaml 指个模型就能跑内置环境：

git clone https://github.com/NVIDIA-NeMo/Gym.git && cd Gym
uv venv --python 3.13.14 && source .venv/bin/activate && uv sync
风险1,491 个未结 issue，问题排队比修得快；上手要自备模型 key 或本地推理服务；深度绑定 NeMo 生态，换框架要重写适配层；判分器质量决定结论，环境写错就是错指标。
