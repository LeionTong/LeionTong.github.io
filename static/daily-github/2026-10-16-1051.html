REA morluto/rea

⭐ 273,087 · 近30天 +272,673（Trending 日榜/周榜双第一） TypeScript · MIT 最近提交 10-16 · release rea-agents 6.5.0（10-14）

定位一个 MCP：让 agent 从程序运行行为一路逆向到二进制，读伪代码、汇编、字符串与调用关系。

痛点逆向长期靠 GUI 工具加人工翻页，结论难留痕；agent 想插手却没有结构化的证据接口。

付费安全、兼容性、逆向工程团队，替代 IDA Pro 一类按席位/年费的工具与「买工具再堆人天」。

规模化目标覆盖原生二进制、Go、Electron、SQLite，接入方式是标准 MCP，多平台同一套流程。

边际低 · 纯 CLI 加 MCP，分析算力与已有 Ghidra/Hopper 复用，新增用户不增加运维。

验证npx rea-agents setup，再 npx -y rea-agents@latest analyze-javascript-application /path/to/app --json（静态 JS 分析不需要原生引擎）。

风险原生二进制分析仍依赖 Ghidra/Hopper/IDA，不是全自带；建仓半年冲到 27 万 star，热度与工程深度不匹配；原生分析在 Linux 与 Windows 上的成熟度不一致。

Bifrost maximhq/bifrost

⭐ 8,840 · 近30天 +2,295 Go · Apache-2.0 最近提交 10-15 · release transports/v2.3.0（10-13）

定位高吞吐 AI 网关：一个 OpenAI 兼容端点接多家模型与 MCP，附带故障转移、语义缓存、护栏与密钥管理。

痛点多供应商切换、限额、可观测与密钥治理散在各处，自研网关又要把重试与缓存重做一遍。

付费已经在按调用量买模型的企业团队，把它当统一入口，省的是重复接入与宕机成本。

规模化HTTP 与 Go SDK 两种接入，配置可用文件/API/Web UI，跨行业交付不需要定制。

边际低 · 单个 Go 二进制或容器，推理算力仍由客户自己的账号承担。

验证docker run -p 8080:8080 maximhq/bifrost，再向 /v1/chat/completions 发一次带 key 的请求。

风险网关赛道拥挤，LiteLLM、Portkey 与各家 SDK 自带路由都在同一位置；差异化靠性能与治理深度，功能容易被追上；开源核心与企业版边界需自行核对。

⭐ 1,518 · 近30天 +322 Python · Apache-2.0 最近提交 10-16 · release v0.1.8（10-12）

痛点语音模型的服务化没有 vLLM 那样的现成栈，生成、声码与流式的调度和传输都要自己拼。

组合观察

五项都在把过去按席位、按调用量、按云账单收费的部分迁回自有栈，交付形态统一是「可自持的软件 + 一条命令验证」，这也是它们能同时冒出来的原因。风险也一致：都不自带客户，谁先把治理、备份与运维补齐，谁才接得住迁移。
