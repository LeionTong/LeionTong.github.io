⭐ 7,731 · 近 30 天 +7,731（10-21 建仓，等于全部） TypeScript · Apache-2.0 最近提交 11-08 · v0.1.38

⭐ 2,059 · 近 30 天 +2,059（10-19 建仓，等于全部） Rust · Apache-2.0 最近提交 11-07 · v0.20261105.4

定位替代 cargo 的 Rust 增量构建器，守护进程把已编译状态留在内存里，改一个函数只重编那部分，再接回原来的产物。

痛点cargo 改一行要重走类型检查与代码生成，大仓一次十秒起；热重载工具只换来页面刷新，编译时间照旧。

付费安装脚本与 canary 渠道免费，背后公司是 indexable；买方省构建机时长与等人时间，能收钱的是团队版与 CI 侧加速。

规模化一条 curl 装到 macOS 与 Linux，同一守护进程提供 build、check、run、test、bench 五个子命令。

边际低 · 本地二进制，不租云端算力；代价是内存，小项目也要几个 GB。

验证curl -fsSL https://ix.dev/blaze | sh，在任一 Rust 仓 blaze build 全编一次，改个函数再编；README 的 ripgrep 例子是 508ms 降到 56ms。

风险官方写明 v2 还没在 Windows 跑过、数字未测；建仓 20 天积了 486 个未关 issue；自带 Rust 工具链，与项目 pin 的版本可能不一致，CI 仍要 cargo 兜底。

今日首选

TokenEconomizer（microsoft/TokenEconomizer）。企业已经在为 token 账单立项，控制成本的工具比换模型更容易被批准。它不改智能体，按仓生效，降幅有论文里的实测数字，最窄的一步是插进现有工作流。v0.1.0 的成熟度不够，但买方与证据都已到位。

组合观察

这五件都在把开发过程中的固定开销换成可替换的件：IDE 席位、一次构建的等待、缓存与向量库的账单、每个 token 的钱、每个人的协作席位。共同动作是先在自己机器上跑通，再按用量算钱；开源负责替换，签约落在部署、支持与用量上。替换的门槛越低，原厂按席位收的年费越难维持。
