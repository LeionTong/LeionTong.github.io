NO.01 · AI coding · 多智能体

一句「做得更好玩」，Claude Code 用动态工作流把整款即时战略游戏推完 12 个版本

AI coding 多智能体 游戏
事件简述

10 月 20 日，Simon Willison 发布浏览器端即时战略游戏 Battle Drones：12 个大版本、321 次提交，几乎全部由编码 agent 完成，主力是 Claude Code。他从 7 月的 Claude Fable 5 起步，10 月换到 Opus 5.5，全程几乎没有读过代码，而 TypeScript 本身也不是他熟悉的语言。

转折发生在 v4。他只给了一句「This game isn't fun enough yet. Make it a LOT more fun.」，在 Claude Code 的 Ultracode 模式下触发动态工作流（官方说法是用一段 JavaScript 脚本同时编排多个子代理）。任务从当晚跑到次日凌晨，agent 跑了上千局模拟试玩，用结果重新平衡单位、加新单位与新模式。它自己写的发布说明里给出两组数字：在 1,200 局 AI 对 AI 的普通难度测试中，25 分钟仍未分出胜负的对局占比从 14% 降到 0.9%；落后 800 以上资源的一方最终翻盘的比例从 24% 升到 46%。此后 v5 把整套 3D 模型直接写成 TypeScript 代码，v12 用麦克风可及范围内的音频报文做双机联机。

关注理由

真正值得记的不是它能跑，而是目标本身是主观的——「好不好玩」被交给 agent，再由它自建模拟对局当评测器闭环调参。这是编码 agent 从写函数走到做产品判断的一个具体样本，也解释了为什么这一轮的长任务需要动态工作流而不是单轮对话。局限同样清楚：评价标准由 agent 自己定、自己打分，人只在最后做游玩体验验收；单一项目、单一作者，换一个代码库能否复现还没有证据。

NO.02 · AI Agent · 长程任务

Notion 重写 agent 底座：单任务从 5 分钟拉到 24 小时，靠路由把成本压掉九成

AI Agent 长程任务 计费
事件简述

10 月 19 日，Notion 发布第六代 agent harness，同时上线新的 Auto 模型路由与双层 credit 体系（11 月 2 日起对现有客户生效）。新底座让每个会话跑在独立服务上，用队列化的 worker 循环推进，官方称任务可以跨重启续跑，单个任务运行时长从 5 分钟提升到 24 小时以上；agent 获得独立的计算机与浏览器，能用写脚本代替反复消耗 token；长对话按各家原生方式压缩，大体积工具结果移出上下文窗口。

Auto 会按任务挑模型：简单请求走快而便宜的，分析与多步 agent 任务走更强的，某个模型卡住时改投另一家。Notion 称在 20 多个常见任务上，Auto 的效果接近 Opus 5.5 与 Astra，平均成本低约 90%，折算下来 credit 能用约 10 倍。另有一项「Review for me」，在 agent 执行动作前由另一个模型判断是否安全。企业侧开放自带模型密钥的私有 alpha，Business 与 Enterprise 席位每月含 1,500 个 Standard credit 与 500 个 Select credit。

关注理由

长任务与成本是 agent 落地的两个硬约束，Notion 的处理方式是把「能跑多久」和「花多少钱」拆开治理：时长靠独立服务与压缩，成本靠路由，风险靠执行前的第二模型复核。需要打折看的是「接近前沿模型」属厂商自测、任务集自选；而 credit 与席位绑定之后，团队换平台的迁移成本会明显上升。

NO.03 · AI Agent · 运维

Grafana 把发现、诊断、改码串成一条链，但修码这一步停在 PR 等人工合并

AI Agent 可观测性 AI coding
事件简述

10 月 20 日 ObservabilityCON 2026，Grafana Labs 公布一批面向 agent 化运维的更新。Assistant Watchers 转为正式可用：用自然语言说明要盯什么、选好数据源，watcher 自己从历史遥测里学基线，模式变化时给出带证据的发现，并走现有 Grafana Alerting 派发，严重发现可直接拉起一次 Investigation。Grafana Managed Sandboxes 进入公开预览：Assistant 在受控云环境里克隆仓库，结合线上遥测定位问题、准备修复，再开 PR 交人审核。Agent Observability 支持 OpenTelemetry 后也转为正式可用，agent 的活动、token 与成本按与其他服务相同的标准上报。

同周发布的 2026 可观测性调查（300 名 IT 与工程负责人）给出两个比例：68% 已把 AI 用于可观测性推进到试点或生产；85% 能接受只读排查，能接受完全自主修复的只有 52%。另一份由厂商资助的 IDC 白皮书称，使用其 AI 工具的客户平均故障恢复时间下降 63%。

关注理由

这条链的关键设计是修码环节默认只到 PR：agent 可以读线上遥测、改代码，但合并仍要人点。等于在运维场景给编码 agent 划了一条可审计的边界，也把「上下文」从聊天记录换成了仓库代码与生产行为。门槛不在模型而在遥测覆盖与权限治理——修复质量取决于代码与运行时能否对上；只读与自动修复之间 33 个百分点的差距，说明信任还在建立中。

NO.04 · 具身智能 · 产业

工信部给出全年口径：人形机器人整机产量预计破 10 万台，上半年已超 4 万台

具身智能 人形机器人 政策
事件简述

10 月 19 日国新办发布会上，工信部科技司司长魏巍介绍，今年上半年我国人形机器人整机产品突破 400 款、产量超过 4 万台，预计全年整机产量将突破 10 万台。他给出的另一个数字是场景侧：通过人形机器人与具身智能实景实训专项行动，相关产品已在仓储物流、餐饮零售、家庭服务等 300 多个重点场景验证和部署。

下一步的动作包括：对运动控制、仿真模拟、触觉传感等关键共性技术「揭榜挂帅」；鼓励商贸企业开放场景做实训验证；发布《国家人形机器人产业标准体系建设指南（2026 版）》并建设开源社区；构建产业监测体系，加强产品质量、网络与数据安全方面的检验检测，并开展伦理治理。

关注理由

从几百台样机到十万台年产量，说明结构件、关节模组与整机产线已经能承接批量订单；但 300 多个场景是「验证部署」，不等于规模复购，真正要看的是单机日均有效作业时长与故障率。标准体系与检测要求落地后，小团队整机出货的门槛会被实质抬高，利好已有量产能力与真实场景数据回流的厂商。

NO.05 · 推理基础设施 · 开源

DeepSeek 开源生产推理框架 DeepInfer，同一套代码同时支持 SM100 与昇腾 950

开源 推理 国产算力
事件简述

10 月 20 日，DeepSeek 在 GitHub 以 Apache 2.0 开源 DeepInfer，称这是支撑其大规模生产服务的推理框架。当前只支持 DeepSeek-V4.1-Flash 一个模型，硬件上同时支持 NVIDIA SM100 GPU 与华为昇腾 950 NPU。

仓库列出的能力包括：FlashMLA、DeepGEMM、DeepEP、TileKernels 等自研算子；Attention DP 配均衡 CP、MoE 专家并行配 EPLB；DSpark 投机解码并按置信度调度校验；SWA 有界重放以削减解码前的预填充开销；零开销批调度；batch-invariant 推理与确定性采样（均限 NVIDIA）；以及正则、JSON Schema、EBNF 三类结构化输出约束。官方明确这是一份离线推理版本，完整服务所需的 KV cache 系统、VE/Prefill/Decode 分离与多副本负载均衡并未包含。项目注明最初基于 vLLM 构建，也参考了 SGLang 与 TensorRT-LLM。

关注理由

把生产推理栈摊开，意味着同样的模型可以在自有集群上复现官方吞吐，而不是只能比价调用 API；SM100 与昇腾 950 写进同一套代码，对国产算力的适配给出一个可跑、可测的参照。缺口也要看清：缺 KV cache 与 PD 分离，离开箱即用的服务还有距离，且只面向单一模型，换模型需要自己改算子与并行配置。

GitHub https://github.com/deepseek-ai/DeepInfer ；The Next Web https://thenextweb.com/news/deepseek-deepinfer-open-source-inference-engine ；AI Weekly https://aiweekly.co/alerts/deepseek-open-sources-deepinfer-its-v41-flash-serving-stack
