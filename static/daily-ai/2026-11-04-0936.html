NO.01 · 模型发布 · 长程智能体

美团发布 LongCat-2.5，1.6 万亿参数的验收标准从写对代码改成做完项目

模型发布长程智能体国产算力原生多模态
事件简述

11 月 2 日，美团龙猫发布原生多模态模型 LongCat-2.5，定位长程智能体任务。总参数量 1.6 万亿，每个 token 平均激活约 480 亿，采用混合专家架构，与上一代 LongCat-2.0 同量级；把视觉信号表示为多层级离散 token，主干以统一 token 形式处理视觉与文本，从而支持 Visual Coding、创意设计与 3D 任务。训练侧加入更多长程轨迹数据，配合大规模长程强化学习，并把真实 Agent 的失败轨迹改造成可复现、可验证的训练任务，围绕数据合成、环境构建与跨 Harness 混合训练扩展链路。

入口为 longcat.ai 官网与 LongCat API，接口同时兼容 OpenAI 与 Anthropic 两种通行格式，可接入 Claude Code、Codex 等编程智能体；本次未开源权重，上一代 2.0 仍以 MIT 协议开放。美团称训练全程在国产算力上完成，是国产算力上目前最大的训练任务；单卡显存不足 80GB 的约束下，W4A4 方案相对 W8A8 INT8 基线，预填充与解码吞吐分别提升 43.3% 与 42.77%，首 token 等待降低 15.91%、每 token 生成耗时降低 19.72%；长序列 SFT 上，FSDP 单卡吞吐较 DDP 基线提升 86%。

关注理由

这一代的考核对象从单段代码换成完整项目，长程智能体能力被写成可横向比较的公开指标，代价是评测子集与提示设置各不相同，不能直接换算成全面领先。

双接口兼容把迁移成本压到改地址与模型名，真正的验证落在自家 Agent 循环的兼容性，以及长上下文、步骤多、需要中途改路时的稳定性；权重未开源意味着可复现性要等第三方复测，工程收益的数字也需要在自有负载上重测。

NO.02 · Agent 基建 · 接口

Anthropic 让 Messages API 在服务端缓存会话，长对话请求体从 800KB 压到 1.8KB

Agent 基建长会话首 token 延迟API
事件简述

11 月 2 日，Anthropic 为 Messages API 推出 message threads 公测。代理首次上传完整会话，之后每轮只发送新增消息与上一条回复的 ID，由服务端临时保存并重建上下文；调用侧只需加 thread 参数与 beta header。官方口径是在 50 万至 100 万 token 的 Claude Code 请求上，首个 token 的中位延迟降低约 35%，长对话请求体积从约 800KB 降到 1.8KB。

线程仅可追加，5 分钟无活动即过期，没有列表、读取、删除接口；Claude 每轮仍读取完整会话，token 计费与速率限制不变，因此这是提速而不是降本。该能力在 Claude Platform、Claude Platform on AWS、Claude in Microsoft Foundry 与 Claude on Google Cloud 按标准费率提供。

关注理由

长会话 Agent 的瓶颈从模型能力转到请求往返，把会话状态交给服务端是这类产品化的关键一步；只省时间不省钱，说明延迟与成本在 Agent 基建里是两条独立的优化线。

五分钟后过期与只可追加这两条限制，决定了线程适合连续作业、不适合当长期记忆，接入方需要自己维护线程生命周期与失败重试，避免线程过期后语义断层。

NO.03 · 模型工程 · 机制可解释

MIT 让 GPT-6 Astra 直接改权重，删掉 0.016% 参数把 Qwen 数学成绩从 7.9% 拉到 48.1%

模型工程权重空间编程机制可解释待复现
事件简述

MIT CSAIL 团队 11 月 2 日公布一组实验：把训练好的 Qwen3.5-0.8B 原始权重直接交给 GPT-6 Astra，由它定位并改动参数，全程不使用梯度下降、不重新训练。Astra 发现模型反复陷入推理循环与第 15、19 层 MLP 写入的某个方向有关，于是从这两层各自的 64 个输出列中减去该方向，共改动 131,072 个权重，约占参数总量 0.016%。

在允许 50 次前向计算的预算下，MATH-500 从 7.9% 升到 48.1%、GSM8K 从 13.8% 升到 67.1%、IFEval 从 21.0% 升到 62.3%，MATH-500 上触及 32,768 token 上限的回答比例从 93% 降到 33.1%；把预算压到 10 次或 25 次，循环几乎不改善。对照实验里，用同一手法处理很少循环的 Gemma 3 270M，MATH-500 只从 6.8% 升到 7.7%。团队另有两例：无训练数据与梯度、从零写出游戏策略网络，超过 1 亿步 PPO 训练的模型；给小车控制网络改 3.5% 权重加入「先后退蓄力，再全速前进」的控制路径，成功率从 0 升到 100%。

关注理由

收益主要来自修掉阻碍已有能力发挥的循环，团队自己的结论就是能移除障碍、补不上模型本来不具备的能力，把 6 倍当成能力跃升会误判来源。

如果大模型能在自然语言与权重空间之间当翻译器，不运行模型就能审查模型会打开一条新路径；目前结果全部由作者自行报告、尚无独立复现，另有研究者公开的同类实验里出现过一个任务用测试集拟合、结果被判无效的案例，复现与规则约束是下一步。

NO.04 · 具身智能 · 基座模型落地

小米具身基座模型在汽车工厂首次完成 8 小时整班作业，青年公寓进入试运营

具身智能VLA产线级验证长程任务
事件简述

11 月 3 日，2026 世界互联网大会在浙江乌镇开幕，小米集团获颁大会「杰出贡献奖」创新突破类奖项，小米机器人业务「面向规模化落地的通用机器人操作基座模型关键技术」获大会「领先科技奖」。峰会期间小米披露两项落地进展：汽车工厂总装车间的中控台侧盖板排序工站首次完成 8 小时连续作业，满足工站全天生产需求，作业中可自主纠偏并与产线系统级协同。

底座是两代模型：VLA 大模型 Xiaomi-Robotics-0 采用大小脑混合架构，使用消费级显卡即可实现 80 毫秒推理延迟；具身基座模型 Xiaomi-Robotics-1 使用 10 万小时真实操作轨迹预训练，在未见环境与未见任务上呈现稳定的规模定律收益，2026 年 7 月在 RoboCasa 365、RoboDojo 两个榜单综合排名第一。家庭场景中，基于 Xiaomi-Robotics-1 搭建的 Agent 系统在小米青年公寓启动「试运营」，已跑通连续超 30 分钟、覆盖 3 个房间、包含 50 多项任务的长程任务链。

关注理由

同一套基座同时承接工位与家庭，训练数据来自自有制造与生活场景，这条闭环是当前具身智能最稀缺的资产；8 小时整班作业把验证从单个动作推进到产线级协同，家庭侧的 30 分钟长程任务链则直接考验泛化。

试运营的口径还留了两个待观察项：工厂侧只公开单一工站，家庭侧只公开一套公寓，规模化复制时的任务覆盖率与异常处置策略，才是采购方真正要核的指标。

NO.05 · 终端智能 · 语音交互

前百川联创的 Orilo 用双层架构做纯语音个人助理，被打断后重新开口 1.08 秒

终端智能全双工语音Personal Agent交互连续性
事件简述

前百川智能联合创始人焦可创办的 Echotime 推出纯语音个人助理 Orilo，把交互层与执行层拆成两层：前端挂低延迟轻量语音模型，负责极速收听、捕捉情绪与接话；后端挂高推理 Agent，在幕后读邮件、调接口、查日历。前端在后台跑任务时具备「边干活边闲聊」的控场能力，用「hmm」「uh」一类拟声词填补等待，避免执行期出现对话死寂。

在 Full-Duplex-Bench 里，Orilo 被用户打断后重新开口耗时 1.08 秒，是测试中最快的，对比 GPT Realtime 的 1.50 秒与 Gemini Live 的 2.62 秒；产品主打 Morning Brief，把个性化资讯、日程与待办放进同一段早间对话。团队 2025 年做的 AI 电台「来福」次日留存一度达到 40%–50%，Orilo 面向海外市场探索商业化空间。

关注理由

语音助理的竞争点落在打断后重新开口的时延与执行期的对话连续性，这两项决定用户是否还觉得在跟智慧生命沟通；1.08 秒已经压在常见的心理阈值之内。

极速的双层拼装以牺牲鲁棒性为代价，实测中出现过后台接口没有调通、前端仍然宣告「已办妥」的情况，说明交互体验的进步还没有同步到任务闭环的可靠性，语音入口要真正承接办事，执行结果的可核验比接话速度更重要。
