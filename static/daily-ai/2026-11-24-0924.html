NO.01 · 编码智能体 · 代码评审

Anthropic 推出 Claude Ship，智能体接管 PR 修复与合并审批

PR Steward 处理 CI 失败、合并冲突与评审意见，改完在评论里写明改了什么、怎么回退Claude Approvals 按仓库配置文件里的规则判定能否合并，PR Steward 没有审批权在 Claude Code 里执行 /ship 触发，Claude Team 与 Enterprise 档的 GitHub 仓库可用
事件简述

11 月 23 日，Anthropic 发布 Claude Ship，把自动修复与受策略约束的合并审批接入 Claude Code。三个组件分工明确：Code Review 负责在合并前标出问题，该能力 2026 年 3 月推出、10 月转为正式可用；新加入的 PR Steward 负责修复，响应失败的持续集成检查、合并冲突，以及来自 Code Review、外部开发工具或同事的评审意见，改动会在 PR 下写明改了什么并给出回退办法。

开发者在 PR 讨论里用 @claude 下指令介入修复，@claude stop 可停止自动介入。PR Steward 被限定为修复角色，不能自行批准改动或合并。合并授权交给 Claude Approvals：它读取仓库配置文件里的治理规则，可同时参考 Code Review 结论与自定义的自然语言分类器，例如允许智能体批准常规文档更新、涉及业务代码的改动仍需工程师签字。当前为 beta，面向 Claude Team 与 Enterprise 档的 GitHub 仓库，也可对整仓开启，让每个新提交自动进入评审与修复循环。

关注理由

PR 流水线里最后一公里的三个动作——发现问题、动手修、决定能否合并——被拆成三个角色，写权限与批准权限彻底分开，修代码的一方拿不到放行权。治理点从人在界面上点按钮，移到仓库里的一份策略文件，权限因此可以被评审、被版本化。

对自建编码智能体流程的团队，这套分工是可照搬的边界：修复动作必须留可回退的说明，自动审批必须挂在显式规则上。真正需要观察的是策略文件写不好的时候，会不会变成另一种形式的人工阻塞。

NO.02 · 智能体基础设施 · 执行沙箱

AWS 发布 Strands Decider v2 与 Box CLI，给编码智能体加执行沙箱

五个基于 Gemma 4 的决策模型，从边缘轻量版到 31B 参数，Apache 2.0 许可不再生成文本，改为对预设选项打分，并给出可判断何时转人工的置信度Box CLI 隔离 Claude Code、Codex、Kiro CLI，密钥存在沙箱外、按策略注入
事件简述

11 月 23 日，AWS 发布 Strands Decider v2，同时放出 Box CLI。Decider 是一类不做文本生成、只对给定选项打概率分的模型，用来驱动工单路由、工具选择这类工作流。v2 建立在 Google Gemma 4 架构上，共五个开权重模型，参数从边缘轻量版到 310 亿，以 Apache 2.0 许可发布在 Hugging Face 与 Strands Decider 仓库。新版能处理更长的输入，包括多步执行日志，便于智能体之间互相协作，并细化了置信度分数，用于判断何时自主执行、何时升级给人工。

AWS 称已在主工单系统内部署该模型替换 Claude Sonnet 4.6，标注成本下降 98%、工单响应时间缩短 78%；内部实验中它还用于驱动机器人手臂、评估其他智能体、把常规查询路由到更便宜的模型。Box CLI 则为 10 月开源的 Strands Box 操作系统沙箱补上命令行入口，隔离 Anthropic 的 Claude Code、OpenAI 的 Codex 与亚马逊的 Kiro CLI。开发者用策略规定文件访问、shell 命令与可连网络主机，智能体可以在无人值守下连续执行，但被限制在边界内；API 密钥与 AWS 令牌存放在沙箱外，只在策略允许的请求离开沙箱时注入。

关注理由

把生成式输出换成在候选动作上打分，适合高频、低创造性的决策点：路由、选工具、判断是否需要人来接手。这类模型小、便宜、可自托管，正好填在智能体循环里最费 token 的位置。

Box CLI 处理的是另一侧风险。编码智能体为了少被打断普遍关掉权限确认，命令执行、文件改动与工具调用不再有人过目，沙箱加凭证隔离是目前唯一可落地的约束方式：模型看不到凭证，泄露面从模型上下文收敛到策略本身。两条护栏一条管选什么、一条管能碰什么，缺一条都不成立。

NO.03 · 智能体治理 · 身份与权限

Workday 完成收购 C1.ai，用入离职事件管住智能体权限

权限绑定入职、调岗、离职事件，覆盖邮件、CRM、代码仓库与云基础设施智能体按需取得访问，任务或角色结束即收回，代员工行事只拿该员工权限的子集敏感变更需人工批准，配置文件里的明文密钥改为保险库引用
事件简述

11 月 23 日，Workday 宣布完成对 C1.ai 的收购，交易金额未披露。该交易 10 月 13 日签约，原定在其 2027 财年第四季度内交割。C1.ai 做的是人与智能体共用的身份治理：因为入职、调岗、离职本身就是 Workday 记录的事件，权限可以直接挂在这些事件上，在邮件、CRM、代码仓库、财务系统与云基础设施之间同步授予或收回。

按双方公布的口径，智能体在需要时取得访问，任务或角色结束后立即失效；代某位员工行事的智能体只拿到该员工权限的子集，自主智能体则适用更严的监督。平台还提供发现未获批 AI 工具、智能体与凭证的能力，并对敏感变更要求人工批准，把配置文件中的明文密钥替换为保险库引用。Workday 称其客户超过 11,500 家，财富 500 强覆盖超过 65%，收购后把自己定位为人与智能体的身份治理层。

关注理由

智能体大规模上岗之后，权限生命周期是最实际的管控点：谁代表谁、能拿到多少、什么时候失效。把智能体身份挂到人力事件上，访问会随组织变动自动收敛，不必靠定期盘点补漏。

对做企业级智能体平台的一方，这套模型会成为客户的默认期待：智能体要有可追溯的身份、可预设的权限子集、可强制的人工闸口。谁先在身份层给出这套能力，谁就先拿到进入核心系统的资格。

NO.04 · 智能体商业化 · 责任划分

美国多家大行封禁第三方智能体，Wells Fargo 风险自负条款生效

更新后的客户协议写明：使用任何 AI 智能体风险自负，11 月 24 日生效摩根大通禁止第三方智能体用客户凭证登录，花旗、PNC、Citizens 相继改条款亚马逊封禁 Meta 的 Muse 下单，美联航禁止个人智能体代订机票
事件简述

Wired 11 月 22 日报道，美国多家大型银行正在把第三方 AI 智能体挡在客户账户之外。Wells Fargo 与数百万客户的更新协议于 11 月 24 日生效，条款原文写明使用任何 AI 智能体风险自负。摩根大通在 10 月下旬修改条款，禁止第三方智能体以客户凭证登录；美国银行同日提示客户不要把登录信息交给智能体；花旗 11 月更新在线用户协议，客户授权第三方智能体产生的活动由其本人负责，凭证泄露或账号被入侵之后的损失同样适用；PNC 于 11 月 18 日改条款，Citizens 通过邮件发出同类提示。

据 Wired 与 TechCrunch 的报道，这等于是先用合同条款把责任划给客户，早于任何立法或监管给出定论。同一批银行在收紧外部智能体的同时也在扩建自家工具：Wells Fargo 的生成式助手交互量超过十亿次，花旗有以智能体为中心的内部开发平台。冲突不止于银行：亚马逊已封禁 Meta 的 Muse 在其平台下单，美联航禁止个人智能体代客订票。运通则表示，智能体买多了之类错误未来可能通过卡组织获得赔付。

关注理由

智能体进入真实账户与支付环节，先卡住的环节是合同与责任，产品能力退到其次。以客户凭证登录这条路径正在被封死，第三方智能体只能走银行许可的接口，支付与身份验证的接口化会因此加速。

对做终端入口与随身智能体的一方，这意味着代操作能力必须建立在被服务方认可的授权通道上：凭证代管、单次授权、可撤销权限都会成为准入门槛。先在合规接入口上留出余量，比事后改产品形态便宜得多。

NO.05 · 具身智能 · 行业标准

工信部五项人形机器人标准发布实施，智能化能力分 L0 至 L5

2026 年第 30 号公告，MIIT/TC8 归口，覆盖能力评价、关键零部件、训练三方向智能化能力分级围绕感知认知、决策学习、执行表现、协作交互四个维度研究机构解读为竞争重点从演示转向可验收，当日人形机器人板块走强
事件简述

工业和信息化部发布 2026 年第 30 号公告，由人形机器人与具身智能标准化技术委员会（MIIT/TC8）归口管理的五项人形机器人领域标准正式发布并实施，覆盖智能化能力评价、关键零部件、人形机器人训练三个方向。其中《人形机器人 智能化能力分级》围绕感知认知、决策学习、执行表现、协作交互四个维度，建立 L0 至 L5 的分级框架。

11 月 23 日，多家财经媒体与研究机构就此给出解读，华龙证券的机械设备行业报告认为行业竞争重点正从演示转向可验收。当日 A 股人形机器人板块午后走强，宇树科技以 20% 幅度涨停，市值回升至约 2,863 亿元。政策侧同期还有面向养老场景的配套文件，鼓励发展服务机器人、智能穿戴与外骨骼等产品。

关注理由

分级框架落地后，采购与验收有了共同口径：L 级别对应可测的能力门槛，关键零部件与训练各有一套标准，报价单与验收清单都要跟着改。此前各家自说自话的能力描述，会逐步被替换成可核对的条目。

对做具身整机与场景交付的一方，标准先行意味着需求描述从能演示变成能按级别验收。早期把能力按级别拆开自评、并留下对应测试记录的团队，在投标与验收环节更容易说清边界；反过来，只有演示视频没有分级依据的方案，会在采购评审里失分。
