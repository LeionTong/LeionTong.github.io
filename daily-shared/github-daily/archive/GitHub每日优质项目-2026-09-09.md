**1. HyperFrames**（heygen-com/hyperframes）｜⭐ 47,810（今日 +2,627 / 本周 +3,886）｜TypeScript · Apache-2.0 · 最近提交 2026-09-09

- 一句话定位：把 HTML/CSS 与可寻址动画确定性地渲染成 MP4 的开源框架，本地 CLI 或 Agent 技能两种入口。
- 解决什么痛点：视频生产至今靠人拖时间轴、改一处要重导一遍；它让视频变成代码——改 HTML 就是改视频，可 diff、可模板化、可批量。
- 谁会付钱 / 怎么收费：替代 Creatomate / Shotstack / Bannerbear / Plainly 这类按渲染分钟计费的 API；也可自建渲染服务按条或按时长卖。Apache-2.0，无分成义务。
- 规模化判断：营销短视频、数据榜单动画、文档转视频、PR 演示，跨行业通用，模板化交付，不依赖驻场。
- 边际成本：低 —— 渲染器是 headless Chrome 逐帧 seek + FFmpeg 编码，纯 CPU，无专有硬件；但每客户仍消耗实际算力，不严格趋零。
- 快速验证：

```bash
npx hyperframes init my-video
cd my-video
npx hyperframes preview   # 浏览器实时预览
npx hyperframes render    # 渲染出 MP4
```

- 风险与坑：① 需 Node 22+ 与 FFmpeg；② 文档与技能注册中心托管在 hyperframes.heygen.com，技能包走 skills.sh 分发，中文资料少；③ `cloud render` 走 HeyGen 托管，要自主可控必须走本地或 AWS Lambda 路径；④ 与 Remotion 正面竞争，Remotion 生态更成熟。
- 评分：商业化 5 · 规模化 5 · 边际成本 4 · 验证速度 5 · 成熟度 5 → **加权 4.80**
- 备注：本项目在 2026-09-08 期曾被列入「暂不建议碰」，理由为「渲染绑定 HeyGen 云服务」。本次复核 README 与 CLI 文档后确认：本地渲染（headless Chrome + FFmpeg）与 AWS Lambda 自持账号渲染均为一等路径，HeyGen 托管只是可选项，**前次判定有误，本期予以纠正**。

**2. TimesFM**（google-research/timesfm）｜⭐ 32,024（本周 +3,365）｜Python · Apache-2.0（v3 权重为非商用许可）· 最近提交 2026-09-07

- 一句话定位：Google Research 的预训练时间序列基础模型，v3.0 起原生支持多变量与协变量预测。
- 解决什么痛点：需求预测、容量规划、库存与能耗预测过去要么买 DataRobot / AWS Forecast 这类平台，要么自己养一支建模团队；它把「开箱即用的通用预测器」变成一个 pip 包。
- 谁会付钱 / 怎么收费：省的是预测平台的订阅费与建模人力；可变现形态是行业微调服务、预测 API、嵌入自有 BI。
- 规模化判断：凡有时间序列的行业都通用，交付即一个模型服务，不依赖定制实施。
- 边际成本：低 —— 纯软件，`pip install timesfm[torch]` 或 `[mlx]`（Apple Silicon 免 PyTorch），单机可跑。
- 快速验证：

```bash
pip install timesfm[torch]
# Apple Silicon 可改：pip install timesfm[mlx]
```

- 风险与坑：**关键 —— 仓库 README 明确声明，TimesFM 3.0 预训练权重采用独立的 `timesfm-non-commercial-license-v1.0`，仅限非商用、非生产用途**。代码是 Apache-2.0，2.5 及更早权重仍是 Apache-2.0；要做商业交付必须落到 v2.5 权重或自训权重，等于把最强版本的能力让出去一档，或自行承担训练成本。此外 238 个 open issue，且 README 声明「非 Google 官方支持产品」。
- 评分：商业化 3 · 规模化 5 · 边际成本 5 · 验证速度 4 · 成熟度 5 → **加权 4.25**

**3. Mailflare**（hieunc229/mailflare）｜⭐ 2,842（近 30 天未获取到；2026-05-26 建库）｜TypeScript · AGPL-3.0 · 最近提交 2026-09-08

- 一句话定位：跑在 Cloudflare 上的自托管域名邮箱，收件走 Email Routing、数据落你自己的 D1 与 R2。
- 解决什么痛点：Google Workspace / Microsoft 365 / Front 按席位月费，且邮箱数据在别人机房；它用 Cloudflare 免费额度收信，发信只需 $5/月 的 Paid Worker。
- 谁会付钱 / 怎么收费：省的是席位费；可变现形态是替 SMB 与团队做邮箱迁移 + 托管运维，或包装成带品牌的邮箱服务。
- 规模化判断：有自有域名 + Cloudflare 账号的团队都通用，部署形态统一（一个 Worker + D1 + R2），不依赖现场实施。
- 边际成本：低 —— 全按 Cloudflare 用量计费，新增租户只是多一个 D1 库，边际趋零。
- 快速验证：点 README 的 Deploy to Cloudflare 按钮，保持 Worker 名为 `mailflare`，打开 `/setup` 建管理员账号并接入域名（需带 Email Routing / DNS / Zone 权限的 `CF_TOKEN`）。
- 风险与坑：**AGPL-3.0 —— 自托管交付给客户、客户内网使用无碍，但若对外提供托管邮箱服务，会触发 §13 源码开放义务**；强绑定 Cloudflare 平台，迁出等于重写；尚无 release、提交集中在单一维护者，issues 仅 4 个但样本太少。
- 评分：商业化 4 · 规模化 4 · 边际成本 5 · 验证速度 5 · 成熟度 3 → **加权 4.25**

**4. Patter**（PatterAI/Patter）｜⭐ 1,051（近 30 天未获取到）｜Python / TypeScript · MIT · 最近提交 2026-08-24

- 一句话定位：开源语音 Agent SDK，四行代码给 Agent 一个真实电话号码，Vapi / Retell 的替代。
- 解决什么痛点：Vapi / Retell 按通话分钟加价、栈锁死；Patter 把 agent loop、STT、TTS、实时语音、VAD、运营商全部拆开，每层可换供应商（27+ 集成），自带失败转移链与 OpenTelemetry 通话追踪。
- 谁会付钱 / 怎么收费：省的是平台分钟加价；可变现形态是替客服/预约/外呼场景做接入与运维，或自建白标语音 Agent 服务。MIT 无协议包袱。
- 规模化判断：呼叫中心、预约提醒、外呼回访跨行业通用，SDK 交付标准；但受各国电信与录音告知合规约束，落地要按地区适配。
- 边际成本：低 —— 纯 SDK，自有 Twilio / Telnyx / Plivo 账号，无硬件无驻场。
- 快速验证：

```bash
pip install getpatter
```

```python
from getpatter import Patter, Twilio, OpenAIRealtime
phone = Patter(carrier=Twilio(), phone_number="+15550001234")
agent = phone.agent(engine=OpenAIRealtime(),
                    system_prompt="You are a friendly receptionist for Acme Corp.")
await phone.serve(agent, tunnel=True)   # 本地起 Cloudflare 隧道即可接真电话
```

- 风险与坑：最近提交停在 2026-08-24、release v0.7.0 停在 06-30，节奏偏慢；telemetry 默认开启（可 `Patter(telemetry=False)` 或 `DO_NOT_TRACK=1` 关闭，CI 中自动关闭）；每通电话仍要付 LLM/STT/TTS 与运营商的真实分钟费，「零成本」只在编排层成立。
- 评分：商业化 5 · 规模化 4 · 边际成本 5 · 验证速度 5 · 成熟度 3 → **加权 4.55**

**5. HFlow**（Hebbian-Robotics/hflow）｜⭐ 253（2026-08-18 建库）｜Python · Apache-2.0 · 最近提交 2026-09-07

- 一句话定位：机器人与 Physical AI 的多模态数据流水线 SDK（YC S26），MCAP 进、可审计的 MCAP + Parquet 目录出。
- 解决什么痛点：具身数据的脏是隐性的——相机冻结、多流失同步、topic 缺失、重复录制，团队往往训完才发现；零散脚本又无法回答「这批数据跑过什么」。
- 谁会付钱 / 怎么收费：机器人团队为数据质量与血缘付钱（对标 Scale / Snorkel 在具身数据这一侧）；YC S26 有商业主体，可变现点是托管流水线与企业内数据治理部署。
- 规模化判断：MCAP 与 LeRobot Dataset v3 已是事实标准，交付标准化；受众窄但付费意愿高，且 README 明确「无需机器人硬件即可贡献/运行」。
- 边际成本：低 —— 纯软件，输入输出都是文件，无本体、无传感器、无 GPU 集群要求。
- 快速验证：

```bash
uv add hflow
git clone https://github.com/Hebbian-Robotics/hflow.git && cd hflow
uv sync --locked
uv run python examples/quickstart.py    # 无输入时自动合成一段带相机与状态流的 episode
```

- 风险与坑：pre-v1（v0.2.5），建库仅三周、253★、24 个 open issue，成熟度是五项里最弱一环；PyPI 名 `hflow` 的 0.1.x 属于同名旧项目，装错版本会踩坑（官方从 0.2.0 起）；调度态依赖生成 Airflow 3 DAG，从本地跑通到生产排期之间还有一段工程。
- 评分：商业化 4 · 规模化 4 · 边际成本 5 · 验证速度 4 · 成熟度 2 → **加权 4.00**

## 一、今日首选

**heygen-com/hyperframes**（加权 4.80）。视频第一次变成可被 Agent 直接产出的确定性产物——改 HTML 就是改视频，替代的是按渲染分钟计费的那条账单，Apache-2.0 且本地即可跑完。它今日 +2,627、本周 +3,886，是本周 Trending 里唯一同时具备「企业级背书 + 自主可控部署 + 明确可比价对象」的项目。

## 二、组合观察

五条没有一个「新模型」，全部是**把已经收了多年钱的成熟账目拆成可自托管的软件**——渲染分钟、预测订阅、邮箱席位、通话分钟、数据治理工时。共同前提是底层能力（模型、算力、对象存储、电信）已经商品化，剩下能赚的是编排、合规与交付这一层。

第二条信号是**门槛从「能不能做」变成「敢不敢替换」**：三条都在 License 或合规上留了钩子——TimesFM v3 权重非商用、Mailflare 是 AGPL §13、Patter 落在电信合规。商业化之前必须先算清许可边界，这已是本项目筛选中反复出现的结构性成本。
