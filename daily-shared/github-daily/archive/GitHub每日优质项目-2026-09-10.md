**1. Apache Maka**（apache/maka）｜⭐ 5,141（近 30 天 +3,880）｜TypeScript · Apache-2.0 · 最近提交 2026-09-09

- 一句话定位：Apache 孵化中的 Agent 工作台，把每一次模型消息、工具调用、权限决策与终止写成 append-only 的 RuntimeEvent 日志，UI、崩溃恢复与下一轮 prompt 都是这份日志的投影。
- 解决什么痛点：企业不敢让 Agent 上生产，因为事后说不清它改了什么、调了什么、谁批准的。Maka 把可审计做成运行时本身，并公开同模型同 verifier 的 per-task 评测。
- 谁会付钱 / 怎么收费：需要 Agent 操作留痕与合规审计的企业（金融、政企、制造业质量体系），路径是私有化部署 + 企业支持与审计报表层；Apache-2.0 无授权障碍。
- 规模化判断：审计留痕跨行业通用，桌面 / TUI / CLI 共用同一 Runtime Host，交付标准化，不依赖驻场实施。
- 边际成本：低 —— 纯软件分发，无专有硬件，无重人力交付。
- 快速验证：下载 macOS / Windows Nightly 安装包（https://maka.apache.org/en/downloads/），首次启动在 Settings → Models 填自己的 API 或本地模型即可开跑；或源码 `git clone https://github.com/apache/maka.git && cd maka && npm ci && npm run dev`（Node.js 22.19+）。
- 风险与坑：尚未发布 Apache 正式 release，当前只有 nightly 且 Windows / Linux 构建未签名；coding agent 赛道极拥挤，差异化只落在可审计与公开评测，随时被上游 harness 追平。
- 评分：商业化 3 · 规模化 4.5 · 边际成本 5 · 验证速度 4 · 成熟度 4 → 加权 4.0

**2. SkillHub**（iflytek/skillhub）｜⭐ 5,071（近 30 天 未获取到）｜Java · Apache-2.0 · 最近提交 2026-09-09

- 一句话定位：企业私有 Agent Skill 注册中心——发布、版本、命名空间、搜索与 CLI 安装，配 RBAC 与审计日志，Docker / K8s 内网部署。
- 解决什么痛点：企业内部的 skill 散落在个人目录和网盘，无法版本化，也无法管控谁能装谁的、出了事无从追溯。
- 谁会付钱 / 怎么收费：已引入 Agent 的大型企业与政企，按私有化部署与运维支持收费；也可作为 AI 资产纳管模块并入既有中台项目一起报价。
- 规模化判断：凡把 Agent 引入研发或客服流程的组织都需要，交付就是一次容器部署加命名空间规划，可复制。
- 边际成本：低 —— Java 21 + React 19，依赖数据库与对象存储，无 GPU 无专用设备。
- 快速验证：`curl -fsSL https://imageless.oss-cn-beijing.aliyuncs.com/runtime.sh | sh -s -- up --public-url https://skillhub.your-company.com`，再 `npx @astron-team/skillhub@latest publish ./my-skill --namespace my-space` 发一个包。
- 风险与坑：技术栈偏重；企业内部 skill 生态仍在早期，客户若没沉淀 skill就先买了空货架；讯飞背书同时意味着部分客户会在意数据回流。
- 评分：商业化 4 · 规模化 4.5 · 边际成本 4.5 · 验证速度 4 · 成熟度 4 → 加权 4.2

**3. Temps**（gotempsh/temps）｜⭐ 736（近 30 天 未获取到）｜Rust · Apache-2.0 · 最近提交 2026-09-09

- 一句话定位：一个自托管 Rust 二进制，把 Vercel + Sentry + PostHog + Pingdom + Resend + E2B + Datadog 七项订阅并成一套，440+ 操作同时是 CLI 命令并自带 Agent Skills。
- 解决什么痛点：小团队每接一个项目就多叠几张 SaaS 账单，数据还分散在七家厂商。Temps 让部署、追踪、分析、会话回放、邮件、沙箱与 AI 网关落在自己的服务器上，且可由 Agent 直接操作。
- 谁会付钱 / 怎么收费：替代的是每席位每月几十到几百美元的订阅；可变现形态是替客户做私有化 PaaS 交付与运维托管，或打包成行业模板出售。Apache-2.0 无分成义务。
- 规模化判断：凡有 Web 应用要上线的团队都通用，脚本化部署即标准交付，不涉及现场定制开发。
- 边际成本：低 —— 纯软件，新增客户只增加一份服务器实例，无硬件无驻场。
- 快速验证：`curl -fsSL https://temps.sh/deploy.sh | bash`，装完 `bunx @temps-sdk/cli projects list` 确认 440+ 操作可用。
- 风险与坑：覆盖面过宽（69 组 440+ 操作），单点深度可能不及专用工具；尚在 v0.1.0-nightly、建库约 11 个月仅 736★，生产级验证样本不足；替代 Vercel 意味着客户要自己承担运维责任，这是销售而非技术问题。
- 评分：商业化 5 · 规模化 4 · 边际成本 5 · 验证速度 4 · 成熟度 3 → 加权 4.4

**4. Ripwire**（redhat-et/ripwire）｜⭐ 1,834（近 30 天 未获取到）｜C++ · Apache-2.0 · 最近提交 2026-09-10

- 一句话定位：给编码 Agent 的代码库地图——零依赖 C++23 CLI 兼 MCP 服务器，输出带排序的确定性调用图，回答该改哪、会波及什么、要跑哪些测试。
- 解决什么痛点：Agent 靠 grep 加整文件读取找代码，同一个检索付两遍 token。Ripwire 用签名替代函数体（自述省 74.7% 字节），每次回答都标注置信边界与截断情况，并可设 token 预算。
- 谁会付钱 / 怎么收费：省的是编码 Agent 的 token 与等待时间；可变现形态是作为团队级上下文服务按席位收费，或并入既有研发效能平台。
- 规模化判断：凡在用 Claude Code / Codex / Cursor 的团队都是受众，交付就是一个可执行文件或 MCP 端点，零配置。
- 边际成本：低 —— 单二进制零运行时依赖，无 API key、无向量库、无索引服务。
- 快速验证：`RIPWIRE_REPO=redhat-et/ripwire bash -c "$(curl -fsSL https://raw.githubusercontent.com/redhat-et/ripwire/main/scripts/install.sh)"`，然后对自己的仓库跑一次查询并对比 token 消耗。
- 风险与坑：建库仅 6 周、v0.5.0，17 个 open issue，语言覆盖广但各语言深度不一；省下的 token 是省钱而非创收，需要客户已经有可观的 Agent 用量才能算清账。
- 评分：商业化 3.5 · 规模化 4.5 · 边际成本 5 · 验证速度 5 · 成熟度 4 → 加权 4.3

**5. Inspect Robots**（robocurve/inspect-robots）｜⭐ 398（近 30 天 未获取到）｜Python · MIT · 最近提交 2026-09-02

- 一句话定位：Physical AI 的开源评测框架——一次定义 benchmark，就能把任意策略（LLM Agent 或 VLA）跑在任意本体（真机臂、人形或仿真器）上，输出可审计日志并接 Rerun 可视化。
- 解决什么痛点：机器人团队换一个模型或换一个本体，评测就得重写一遍，结果还无法横向比较。它把 Inspect AI 的做法搬到物理 AI，评分、LLM 交互与完整配置都留档。
- 谁会付钱 / 怎么收费：机器人与具身团队为可复现的评测与回归基线付钱；可变现形态是评测体系搭建服务、行业 benchmark 套件与企业内回归流水线部署。MIT 无授权包袱。
- 规模化判断：受众窄但付费意愿集中；交付为标准 Python 包加配置文件，仿真路径与进程内策略均不需要真机，不触发重硬件否决。
- 边际成本：低 —— 输入输出都是文件与日志，无本体、传感器或 GPU 集群强制要求（部分策略需 GPU 服务器，可用 mock 策略跳过）。
- 快速验证：`uv venv && uv pip install inspect-robots && source .venv/bin/activate && inspect-robots setup`，或装插件 `uv pip install inspect-robots-yam` 后用 `inspect-robots "place the fork on the plate"` 跑第一条指令。
- 风险与坑：README 自述 alpha、API 可能在版本间变动；默认策略 MolmoAct2 需另起 GPU 服务器（可用 `agent` 或 mock `scripted` 进程内策略绕开）；建库两个半月、398★，生态插件仍在铺。
- 评分：商业化 3.5 · 规模化 3.5 · 边际成本 5 · 验证速度 4 · 成熟度 3 → 加权 3.8

## 一、今日首选

**gotempsh/temps**（加权 4.4）。它是今日唯一一个能把「替代了哪几张账单」逐项点名、且替代对象都是明码标价的成熟订阅的项目。自托管二进制即交付，不需要实施团队；440+ 操作同时是 Agent 可直接调用的 CLI，运维本身可以被自然语言接管。

## 二、组合观察

五条里有四条卖的都不是模型能力，而是 Agent 用起来之后必须补的那一层：Maka 补留痕、SkillHub 补资产纳管、Ripwire 补上下文成本、Temps 补运行平台；Inspect Robots 把同一套「先有评测与留痕，再谈上本体」的逻辑搬到了物理 AI。

共同形态是清一色的纯软件、私有化部署、Apache-2.0 或 MIT，账都算在替代既有订阅与合规成本上——竞争已经不在授权，而在谁先把替换账算给客户看。

## 三、暂不建议碰

1. **tashfeenahmed/freellmapi**（⭐ 25,232，近 30 天 +7,218）— 聚合 34 家免费供应商 635 个端点成统一 /v1 接口，方向正确但作者自述 "Personal experimentation only"。免费额度受各家用量条款与风控约束，无法作为交付给客户的 SLA 承诺，热度与可商用性无关。
