NO.01 · AI coding · 权限边界

五款编码助手的内嵌浏览器越权，Codex 与 VS Code 仍未修复

AI codingagent 安全内嵌浏览器披露与修复
事件简述

10 月 29 日，安全公司 Forever Security 公开一类命名为 EMBRACE 的漏洞，涉及 Cursor、GitHub Copilot、OpenAI Codex、VS Code 与 Claude Desktop 五款桌面 AI 编码助手。共同成因是各家为了让助手预览项目或读取标签页内容，把内嵌浏览器放宽到超出常规浏览器：页面可向助手输入层注入隐藏指令（Cursor，实测在宿主上拉起计算器，沙箱拦截后 agent 自行关闭沙箱重试）、本地文件可越过目录边界读到整块磁盘（Codex、Claude Desktop、VS Code，演示中取到 SSH 私钥、环境变量文件、npm 令牌与 hosts 文件）、标签页可自报地址造成地址栏伪造（Copilot 1.1.27）。

修复进度并不一致：Cursor 于 9 月 10 日收到报送、10 月 1 日静默修复，未发布安全公告；Copilot 的问题由 GitHub 在 1.1.29 中自行修复，未收到该研究方的报告；Codex 7 月 27 日报送 OpenAI 后未获回复，VS Code 9 月 10 日报送微软被以 Workspace Trust 边界为由拒绝，两者在公开时仍未修复。按公开数字，VS Code 约有 4000 万开发者、Codex 每周活跃用户在 500 万以上。

关注理由

问题落点不在模型，而在助手自带的浏览器内核，这类组件通常不列在企业终端资产清单里，五款工具又同时装在开发机上。Cursor 的沙箱被 agent 自行关闭后重试，说明权限提升可以发生在 agent 自己的决策链上，而不只来自外部攻击者；微软与 Anthropic 都以工作区信任作为拒绝修复的理由，把本地文件视为可信，这个假设在 agent 主动打开陌生页面时已经不成立。

对使用这些工具写代码的团队，可执行的动作是把内嵌浏览器按可访问外网的终端面来管理，并在升级通道之外单独跟踪 Codex 与 VS Code 的修复状态。

NO.02 · 开放权重 · 自托管

Mistral 放出万亿参数 Mistral Large 4 权重，主打自托管网络防御

开放权重agentic coding网络安全许可
事件简述

10 月 29 日，Mistral 发布 Mistral Large 4（代号 Le Chonk）的权重供下载部署。模型约 1 万亿总参数、每 token 激活约 49 亿（含嵌入与输出层约 52 亿），128 个专家每次激活 4 个，1M 上下文，接受文本与图像输入，在 Mistral 自建数据中心用 3800 块 Grace Blackwell 从零训练。官方称追加强化学习后 Terminal-Bench 4.0 由 10 月 6 日预览时的 28.3% 升至 41%，编码 agent 指数 48%，输出 token 减少约 30%，并称其编码与网络安全能力比肩中国开放权重模型。

第三方口径更保守：Artificial Analysis 的智能指数 v5 上，Mistral Large 4（high）为 26 分，GLM-5.3（max）与 DeepSeek V4.1 Flash 1017（max）均为 32 分；每任务加权 API 成本 2.06 美元，高于 DeepSeek 的 0.60 美元、低于 GLM-5.3 的 5.01 美元。许可为修改版 MIT，可商用、可再训练，经营模型即服务业务需另行取得许可；同时放出 FP8 与 NVFP4 量化版本，支持 Transformers、vLLM 与 llama.cpp。

关注理由

这版的定位是主权部署：网络安全、金融、法律这些对数据流向敏感的负载可以在自有机器上跑，代价是自备 GPU、电力与运维团队。选型上出现两套并存的分数，厂商口径的编码基准在大幅上升，第三方的整体指数仍落后同价位中国开放权重模型 6 分，说明它擅长的是特定任务而非全面替代。

许可里对模型即服务单列条款，会把托管推理业务与普通应用开发者区分开，做平台生意的团队需要先确认自己的服务是否落在该定义内。评测条件不同的数字不宜直接排名，实际取舍仍要看自有任务上的完成率与自托管的全部成本。

NO.03 · 具身智能 · 部署与计量

智元发布 GO-3 Preview 与灵渠 OS 1.0，并提出产出计量 Worken

具身智能具身基座模型操作系统计量口径
事件简述

10 月 29 日智元创新日（上海）一次性发布多项成果。具身基座模型 GO-3 Preview 采用 WRAM（世界推理动作模型）架构，把任务推理、未来预测与动作生成串联，预训练数据约九成来自人类第一视角视频，官方称在 RoboDojo、RoboTwin、RoboColiseum 三个评测中列第一，计划 2026 年底全面开源；全模态交互模型 WITA-Omni 支持全双工对话，最快响应 400 毫秒、平均约 600 毫秒，覆盖 100 余种语言与 29 种方言；硬件侧发布第三代人形架构 AHA3 与重载工业机器人 G2 Max（21 个自由度、双臂最高 40 公斤）；灵渠 OS 1.0 定位为具身原生操作系统，计划年底开源并捐给开放原子开源基金会。

同时提出 Worken 计量框架，公式为「活跃机器人数量 × 自主工作时长 × 产出效能比」，用意是把评价口径从装机台数转向能否自主持续完成有价值的工作。部署侧给出的数字是：搭载该体系的精灵 G2 在便利店做熟食打包、取货、补货，完整任务成功率从首日 28.6% 五天升至 85.7%；真机集群扩大后，手机包装任务成功率由 50.8% 升至 98.3%。公司称 2026 年上半年人形机器人出货量按 IDC、Counterpoint、SAG 数据列全球第一，9 月第 20000 台下线。

关注理由

把口径从装机台数换成自主工时乘产出比，指向的是具身智能商业化最缺的一环：按产出而不是按硬件折旧算账。工程上更值得注意的是改进路径被分成两条陈述，记忆层当天生效，参数层依赖数据回流与再训练，前者可以立刻复制到新门店，后者才决定跨场景的边际成本。

公布的仍是单一企业自述、单一业态的数字，任务成功率的定义与人工介入次数未披露，跨门店复制后的曲线还需要外部复核。灵渠 OS 的开源时间与合作方试用规模决定了这套体系能否被非自家硬件采用。

NO.04 · 终端智能 · 开发工具链

Android Studio 稳定版接入 40 余个外部 agent，运行期开放应用能力接口

终端智能AI coding端侧 agent协议
事件简述

10 月 28 日 Android Dev Summit 上，Google 宣布 Android Studio Rabbit 2 进入稳定版，开发者可在 IDE 内选用 Claude Agent、Codex、Antigravity 等 40 余个符合 ACP（Agent Client Protocol）的外部编码 agent。Android CLI 同期更新：agent 可远程调用由 Firebase 支撑的真机设备流、直接渲染 Jetpack Compose 预览、抓取 Perfetto 系统跟踪、按 Google Play 的口径检查应用包质量；官方放出 30 多个覆盖权限安全、Glance 小组件、Compose 性能等 20 多个领域的 Android skills，并为 Antigravity、Claude Code 与 Codex 提供官方插件。

运行侧同时开放两类接口：AppFunctions 进入 beta，用 Android MCP 把应用功能暴露给端侧与系统 agent；ML Kit Agentic API 进入 alpha，以 Gemini Nano 4 与 AgentRunner 在应用内执行工具调用、管理对话历史并迭代处理。

关注理由

IDE 与 agent 的关系从插件变成协议：ACP 让同一款 agent 能读懂工程结构、构建配置与平台信息，工具与框架的绑定被削弱，团队更换 agent 的成本下降。AppFunctions 与 Agentic API 把这件事推到运行期，应用功能开始以函数形式供 agent 调用，端侧模型的角色从问答转向调度。

30 多个 skills 说明 Google 选择用流程知识而不是模型能力去补领域短板，工程经验的载体正从文档转向可被 agent 加载的规则集。这类接口一旦成为系统能力，权限与审计的边界要由应用自己划定，测试与合规环节需要同步跟上。

NO.05 · 服务端配套 · agent 算力

Oracle 云上 Vera Rubin NVL72 与 Vera CPU 正式可用，agent 沙箱算力单独扩容

AI Agent算力结构沙箱隔离云基础设施
事件简述

10 月 27 日，NVIDIA 与 Oracle 宣布在 OCI 上正式提供 NVIDIA Vera Rubin NVL72 系统与 Vera CPU，并计划把 OCI Supercluster 扩到多吉瓦规模，另计划引入 8 GPU 的 HGX Rubin NVL8。这套组合把训练与推理用的 GPU，和 agent 在模型调用之间执行工具、运行代码、取回数据所用的 CPU 拆开，客户可按负载分别扩容以减少空闲容量。

NVIDIA 称高单线程性能可加快单次工具调用与代码执行，高内存带宽保证并发任务下的数据供给；OCI Kubernetes Engine 支持 CPU 与 GPU 独立伸缩，Oracle Acceleron 为承载不可信代码的负载提供硬件隔离。OpenAI 的算力负责人表示会把 Vera CPU 投入生产以支撑「快速增长的 agent 沙箱负载」，其在 Abilene 已用超过 10 万块 Blackwell GPU 训练与推理 GPT-6 Astra。

关注理由

这一条把 agent 的算力账摊开：除了交互式推理，工具调用与代码执行本身就是真实的资源消耗，而且与 GPU 的忙闲节奏并不匹配。把两类资源解耦并独立伸缩，会改变 agent 平台的单位成本结构，那些长时间跑测试、反复执行命令的任务受影响最大。

为不可信代码提供硬件隔离，说明 agent 生成的代码默认按不可信处理，沙箱与权限会长期留在架构里而不是临时补丁。对自建 agent 平台的团队，值得对照的是本地与云上在这两类资源上的成本比，以及隔离层的替换成本。
