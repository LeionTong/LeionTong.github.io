NO.01 · AI coding · 开发基建

Anthropic 公开自研源码控制系统 Scion，日均合并量半年涨超十倍

AI coding 开发基建 Agent
事件简述

10 月 13 日，Anthropic 官方工程博客公开自研版本控制系统 Scion 与代码评审平台 Antique，并说明为何弃用 Git 改用自建方案：2026 年 5 月其主干日均合并约 2500 次，到 9 月已超过 30000 次；主干历史近 100 GB，压缩后的工作副本超过 25 GB，CI 每天执行约 2500 万次代码检出，按 Git 的分布式设计朴素抓取每天会产生 600 PB 以上流量。

Scion 由 7 人团队用 5 个月从 Git 完成全量迁移：客户端默认在线、把 blame / 合并 / 变基等放到服务端，仓库数据分布式存放、无需 packfile 与 refs。团队称参照了 Google Piper 与 Meta Sapling 的经验，并明确 Scion 不是通用 Git 替代品，先公开思路供他人借鉴。

关注理由

这是「AI 写代码」把人类尺度的开发基建顶穿的第一份公开案例：当合并量的增长来自 agent 而非人，为离线协作设计的分布式版本控制反而成了瓶颈。Anthropic 的解法——服务端承接历史查询、客户端按需取数、CI 不必检出整个仓库——正是「agent 永远在线」这一前提的产物。对 AI coding 方向，它说明瓶颈正从模型能力转到构建、CI 与代码评审这些外围系统。

Anthropic 官方工程博客 https://www.anthropic.com/engineering/redesigning-source-control ；Simon Willison https://simonwillison.net/2026/Oct/13/redesigning-source-control-at-anthropic/

NO.02 · AI coding · Agent 可观测性

Claude Code v2.1.300 引入 OpenTelemetry GenAI 语义属性与 AWS 平台上的 advisor

AI coding Agent 可观测性
事件简述

10 月 14 日，Anthropic 发布 Claude Code v2.1.300，共 88 项变更（12 新增 / 13 变更 / 4 改进 / 59 修复）。新增内容集中在运维与治理：trace span 加入 OpenTelemetry GenAI 语义约定属性（如 gen_ai.provider.name、gen_ai.conversation.id、gen_ai.tool.name、error.type），api_request 事件补充按 5 分钟 / 1 小时 TTL 分档的缓存写入 token 统计；服务端工具 /advisor 上线 Claude Platform on AWS，允许主模型在关键节点咨询另一个更强的模型。

同版还有破坏性变更：PreToolUse / PermissionRequest 钩子返回的 updatedInput 现按与模型自身输入相同的规则校验。官方另称桌面应用优化了多会话并行与启动速度。

关注理由

当 agent 从演示走进生产流水线，团队需要的是「这个会话调用了哪些工具、花了多少缓存、错在哪」的可追溯性，而 OpenTelemetry 的 GenAI 语义约定正在成为跨厂商的事实标准。Claude Code 把工具名、会话 ID 与错误类型写进 span，等于让编程 Agent 的运行过程能被既有监控栈直接消费。advisor 这类「主模型干活、强模型把关」的服务端工具，也是在为长任务加一道质量闸。

NO.03 · 具身智能 · AI coding

EmbodiedEvo 让编程 Agent 在机器人任务里自进化，RoboDojo 仿真成绩超官方验证记录

具身智能 AI coding Agent
事件简述

10 月中旬，EinsiaAI 实验室公开论文 EmbodiedEvo（arXiv:2610.18867），把软件工程式的编程 Agent 循环搬到物理世界：Agent 在单个「试炼场」场景里反复执行、观察并修改控制代码，把可复用的 Skills（控制流程与适用条件）与 Lessons（失败模式、约束与恢复经验）沉淀下来，冻结后交给新布局与不同模型上的测试 Agent 使用。

在 RoboDojo-Sim 仿真上，EmbodiedEvo 取得平均分 44.48、成功率 37.82%，论文称超过该基准所有官方验证结果；成对测试中仅靠任务描述就把成功率从 8.50% 抬到 30.17%，Astra 的经验还能把 Sol 与 Luna 的成功率分别提升 8.86 和 5.50 个百分点；相比直接投喂原始交互历史，Skills 与 Lessons 在成绩相当的前提下节省 53% 的执行成本。

关注理由

这条把「AI coding 的自进化」与「具身智能」接在一起：不训练策略权重，而是让 agent 改自己的控制代码，把一次交互中的经验固化成可迁移的技能与教训。经验能跨模型迁移尤其值得注意，说明「产出可用控制知识」与「执行任务」是两种能力，弱执行者也能借用强模型的沉淀。对具身方向，它给出了绕开 VLA 权重堆叠的另一条路，代价是精细插入与液体处理仍然困难（原论文摘要记 44.48 / 37.82%，机器之心报道作 45.08 / 38.95%）。

来源

arXiv https://arxiv.org/abs/2610.18867 ；项目主页 https://lab.einsia.ai/embodiedevo

NO.04 · 终端智能 · AI Agent

阶跃星辰智能体手机 STEPX Neo 今日 10:13 首销，全栈定价 3999 元

终端智能 AI Agent 系统
事件简述

10 月 13 日晚于上海发布的 STEPX Neo 先行版，于 10 月 16 日 10:13 正式首销（10 月 13 日 21:00 已开预售），全栈定价 3999 元，把手机硬件与 Step AOS 1.0 系统、Step Studio 开发工具及 Step 系列模型服务打包销售，购机赠 12 个月、每月百亿 Token 额度。

产品把长期记忆、任务调度与安全机制放进系统层，解锁后默认进入智能体界面，机身背部点阵屏专用于显示智能体的唤醒、聆听、思考等状态；硬件配六麦阵列、低功耗音频感知芯片与自研 Whisper 1.0 拾音算法，官方称音频芯片独立运行 24 小时耗电 1.2%。生态上，个人智能体 Amoo 称已与支付宝、腾讯、携程、滴滴、高德、美团等近百家企业产品打通，首批接入腾讯 WorkBuddy。

关注理由

它走的是与豆包手机相反的路：不靠读屏模拟点击，而让应用带接口进系统。两条路的差别落到现实就是——前者要说服应用方开放自动化权限，后者要逐家谈接入。对终端智能方向，这是一次把「手机入口从 App 迁到智能体」的正面押注，首销后的任务完成率与生态兑现程度才是这类产品能否成立的真实检验。

NO.05 · 具身智能 · 灵巧手

Nature Will 发布 Natura-1，用百万小时人类视频预训练灵巧手模型

具身智能 灵巧手 预训练
事件简述

10 月 13 日，北京具身智能公司自然意志（Nature Will）发布 Natura-1：约 500 亿参数的 MoE 模型，在约 100 万小时第一人称人类视频（约 6170 万个片段、31.8 万种任务、1.4 万个场景）上预训练，再以少量机器人数据后训练，可在约 100 毫秒的观测—动作回路里驱动 20 自由度灵巧手。

在其 12 个能力维度的基准中，Natura-1 于灵巧手平台得 53.4 与 59.1，对照的 π0.5 与 GPT-6 Astra 在灵巧手平台未能得分（换夹爪后分别为 13.5 与 16.7），测试任务的场景、物体与动作组合均不在训练集中。团队还观察到未被示范的涌现行为，如借长杆把够不到的篮子拉近、把扑克牌推到边缘再双手配合拿起。

关注理由

灵巧手自由度高、接触容错低，长期是通用模型的死角；Natura-1 把突破口放在「人类第一人称视频」这一近乎免费的数据源上，并用零样本跨任务表现证明其可迁移。与依赖遥操作采集的路线相比，它把最贵的一环从数据采集挪到了预训练，也顺带得到失败后自动重试的能力。需要注意官方尚未公布权重、API 与授权细节。

机器之心（腾讯新闻转载）https://news.qq.com/rain/a/20261014A09CBS00
