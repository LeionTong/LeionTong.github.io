NO.01 · 具身智能 · AI coding

英伟达开源 ASPIRE 1.0：让编程 agent 给机器人改程序，把修好的经验存成技能库

具身智能 code-as-policy 开源
事件简述

10 月中旬，英伟达 GEAR 实验室在 GitHub 发布 ASPIRE 1.0（Apache-2.0，仓库 554 星），论文编号 arXiv:2607.00272。它的做法是把机器人当成会写代码也会调代码的 agent：agent 在开源的 CaP-X 框架里写 Python 控制程序，执行引擎按每个感知、规划、抓取、控制调用记录多模态轨迹，失败后 agent 顺着轨迹定位问题、改程序、重跑验证，验证有效的修复被整理成可检索、可组合的技能条目，另有一条进化搜索并行生成多个候选方案。

官方给出的结果：换用 Claude Opus 5.5 后，LIBERO-Pro 全部 80 项任务平均成功率 99%，Robosuite 与 BEHAVIOR-1K 的代表性任务 100%；未见过的新长程任务零样本成功率 31%，此前方法约 4%。在真机上，ASPIRE 驱动的机械臂解魔方，耗时随技能库积累逐步下降；仿真是学到的技能也能迁移到不同本体与不同机器人 API 上。

关注理由

这件事的意义在训练产物的形态：不再是又一份不透明的权重，而是一套能读、能改、能 diff 的程序与技能条目，模型升级后整套经验仍然可用。对 AI coding 方向，它也是「agent 看得见执行轨迹才改得对」的一次验证——反馈粒度细到单个调用，修复才可定位。需要留意的是仓库自己写明：执行模型生成的 Python 有完整 import 权限，试验进程与看门狗不构成安全沙箱，真机部署前得自己补隔离。

NO.02 · 模型 · 工具接口

DeepSeek 更新 V4.1-Flash-1017，搜索与抓取接口改为按次收费

AI coding 检索工具 API 定价
事件简述

10 月 18 日，DeepSeek 把 V4.1-Flash 更新到 V4.1-Flash-1017 检查点，网页、App 与 API 同步上线，调用方式与单价不变。官方称新版本在 11 项自报基准上均超过上一版，DeepSWE v1.1 得 77.0，任务完成更快、输出更短。

同期开放自研的 Search 与 Fetch 接口：此前不计费，按公告自北京时间 2026 年 11 月 1 日 00:00 起，按每 1000 次成功请求 5 元收费，空结果与失败请求不计费。官方称底层是自建搜索引擎，索引千亿级网页，并针对 SEO 作弊、GEO 操纵与低质 AIGC 内容做过滤。1017 版权重的许可证尚未公布。

关注理由

模型厂商把检索和网页抓取收进自家 API，搭联网 agent 时可以少接一层第三方搜索服务，工具链更短、时延更可控。更值得注意的是计价单位：按成功请求而非 token 收费，会把 agent 的成本结构从「上下文有多长」推向「工具被调用多少次」，多轮检索型任务的预算测算方式要跟着改。私有化部署前仍需确认权重许可，否则只能走 API。

NO.03 · AI coding · 安全

OpenCode Console 遭未授权访问，1.4% 用户的第三方模型密钥可能泄露

安全 AI coding 凭证管理
事件简述

10 月 17 日，开源编码 agent OpenCode 披露一起安全事件：一个正在下线的旧 Console 系统被未授权访问，约 1.4% 的 Console 用户受影响，即那些在平台里绑定了外部模型供应商的账号，其 OpenAI、Anthropic、Google 等密钥可能已泄露。公司称已逐封邮件通知，未收到邮件即未受影响，正与三家供应商协同处置，并称事件仍在进行、暂不公布技术细节。

据报道，部分受影响用户的账户余额在一夜之间被刷掉数百至上千美元。官方口径的 1.4% 是受影响账号比例，不等于确认被窃取或被使用的密钥数量；只在本地环境变量里放 key、不走 Console 托管的那部分用户不在范围内。

关注理由

攻击者要的不是密码，而是计费授权：一个前沿模型的 key 半天就能跑出数百美元账单，这让「把 provider key 托管在工具平台」从便利变成风险敞口。对团队的直接含义是凭证分层——按项目发短期、限额、可吊销的 key，打开用量告警，别让同一把 key 同时服务本地 CLI 和云端自动化任务。

NO.04 · AI Agent · 运行环境

PilotDeck 2.0 开源：以工作舱隔离多项目，记忆做成可查看可修改的白盒

AI Agent 记忆 开源
事件简述

清华 THUNLP 与面壁智能、OpenBMB 等团队开源的 PilotDeck 2.0（AGPL-3.0）在 10 月中旬发布，国内媒体从 10 月 17 日起集中报道。它把运行单位定为 WorkSpace（工作舱）：每个项目拥有独立的文件系统、记忆库与技能集，多个项目并行时互不串上下文；记忆从生成、抽取、存储到调用全链路可见，用户可以直接查看、修改、删除或固定某条记忆，空闲时后台对零散记忆做归纳并支持一键回滚。系统原生支持 MCP，提供 Web UI 与 CLI，也可用 Docker 部署。截至 10 月 19 日仓库 4,713 星。

关注理由

多项目并行时上下文互相污染、记忆是黑盒，是 agent 落地最常见的两个具体故障，也都不是靠换更强模型能解决的。把隔离单位从「会话」换成「工作舱」、把记忆做成可回滚的显式存储，是工程上能直接搬走的解法。AGPL-3.0 对闭源产品集成有约束，企业采用前需要先确认合规口径。

GitHub https://github.com/OpenBMB/PilotDeck ；AI 潮汐 https://ai-blog.cloud/tool/pilotdeck-2-0-open-source-agent-os/
