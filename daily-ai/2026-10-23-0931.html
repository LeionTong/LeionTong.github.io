NO.01 · AI Agent · 执行环境

Google 把 Gemini 背后的 agent 运行底座开放，每个 agent 一台隔离机器，凭证不进沙箱

AI Agent microVM 隔离 零持久密钥
事件简述

10 月 22 日，Google Cloud 在 AGNTCon + MCPCon 上发布 Agent Compute Engine，为每个 agent 分配一台硬件隔离的 microVM：跑在 Cloud Hypervisor 之上，各自拥有独立 guest kernel 与 root 权限，由 Titanium IPU 提供硅级信任根。这套底座已经支撑 Gemini、Gemini platform、Antigravity 以及 Google 内部的模型评测与强化学习流水线，面向云客户的预览安排在「未来几个月」，价格与具体日期未公布。

成本设计针对 agent 的空转特性：当 agent 结束一次工具调用进入思考阶段，microVM 会 checkpoint 暂停，需要时从快照恢复；只读模板用写时复制共享物理内存，官方称单台服务器可以塞下十倍数量的 agent，20 万 agent 的测试中暂停与恢复耗时低于 500 毫秒，激活速率每秒 500 次。安全侧是零持久密钥：沙箱内不留长期凭证、OAuth refresh token 与服务账号密钥，也访问不到实例元数据服务，只拿到一枚会话级 SPIFFE 身份；调用 Drive 这类服务时，由 Agent Gateway 校验会话身份与出网策略后在沙箱外注入真实凭证。每台 microVM 另配 Hyperdisk 保存工作区，跨天续跑不必重建环境。同期开源的 Agent Substrate 把这套思路搬进 Kubernetes，可在 GKE 试用，兼容 Claude Code、OpenClaw 等外部 harness。

关注理由

agent 平台的竞争重心正从模型能力挪到运行与治理层，这一版把隔离、成本、身份三件事按同一个问题处理：能写代码、驱动浏览器的 agent 需要一道边界，整天闲置的 agent 不该占着硬件，企业还要知道哪个 agent 用了多少 token、以谁的身份。凭证留在沙箱外、身份改成短时，是把这类 agent 放进生产的前提条件。需要打折看的是：预览时间与定价都还没定，密度与延迟数字来自 Google 自测，Agent Substrate 能否吸引 Google 之外的贡献者仍待观察。

NO.02 · AI Agent · 开放标准

Anthropic 把 Agent Skills 标准捐给 Linux 基金会，百万个 skill 有了中立托管方

AI Agent 开放标准 技能生态
事件简述

10 月 22 日，Anthropic 宣布把 Agent Skills 标准捐给 Linux 基金会下的 Agentic AI Foundation。AAIF 由 Anthropic 与 Block、OpenAI 去年共同创立，此前已接收 Model Context Protocol。这次捐出的包括名称、标识、GitHub 组织与 agentskills.io 域名，标准由 Anthropic、Google、OpenAI 等公司的工程师以个人身份维护，David Soria Parra 与 Mahesh Murag 担任 Lead Maintainers。

Anthropic 给出的规模数字：该标准 2025 年 12 月发布以来，已有 70 多个 agent 平台接入，包括 ChatGPT、Cursor、GitHub Copilot 与 VS Code；累计发布 100 万个 skill，装机接近 2.8 亿次。一个 skill 就是一个含 SKILL.md 的目录，里面可以带脚本与参考资料。基金会侧已提出路线图，覆盖版本化发布、正式提案流程，以及面向技能编写者与安装者的安全指引。

关注理由

skill 已经成为 harness 之外的第二层可移植资产，谁保管标准直接影响生态走向。捐给中立基金会与 MCP 当年走的路径一致，企业侧接入一套标准，比逐家适配私有格式省事得多，这也是标准能被跨 harness 复用的前提。变量在细则：提案流程与安全指引还只是路线图，恶意或过期的 skill 由谁审查、版本如何回滚都还没有落定，装机量与实际被调用的比例也是两回事。

NO.03 · AI coding · 本地模型

Recursive 开源 Flint：40B 参数只激活 2.5B，笔记本上跑编码 agent

AI coding 开源权重 本地推理
事件简述

10 月 21 日，由前 Salesforce 首席科学家 Richard Socher 领导的 Recursive 发布 Flint：一个 40B 总参数、每 token 激活 2.5B 的 MoE 编码模型，权重以 Apache 2.0 放在 Hugging Face。官方称在自研推理引擎下，M4 Pro MacBook Pro 上生成速度超过 125 token/s，64GB 显存的 RTX Spark 上超过 150 token/s，支持 512k 上下文，建议控制在 256k 以内。厂商自测分数为 SWE-bench Verified 74.2%、Terminal-Bench 2.1 54.9%；vLLM 已在首日支持，称单张 GB200 在 10 万 token 上下文下单请求解码约 500 token/s。

更值得注意的是研发方式。Recursive 的自动化研究系统 Eureka Machine 参与了数据、训练配方、基础设施与推理优化的几乎所有环节：从 35B 总参数、3B 激活的基线出发搜索专家配置与宽度，定到 40B / 2.5B；把输出层量化到 4 bit，再用 16-bit 模型作教师做离线蒸馏回收精度，官方称量化版与原版差距在 0.7 分以内；还生成了面向 Apple Silicon 与 RTX Spark 的专用算子，其中一个是把整个解码前向融合的 Metal megakernel。小团队加 agent 用不到四个月从零做出这套东西。

关注理由

本地编码模型的可用线在抬高：2.5B 激活就能在消费级机器上给出接近云端水准的 agentic coding 表现，数据不出本机、按量计费归零，这对需要代码留在本地的团队是实打实的选项。它同时是「AI 造 AI」的一次公开检验，可核实的是权重、硬件要求与许可，无法从外部核实的是 Eureka Machine 的实际贡献比例，分数也全部来自厂商自测，团队在换进自己的 agent 流程前应先在自有仓库上复测。

NO.04 · AI coding · 平台接口

Claude API 三年多来首次换代：采样参数被移除，七个 SDK 同时跳大版本

AI coding 破坏性变更 SDK 迁移
事件简述

10 月 21 日，Anthropic 发布 Claude API 版本 2026-10-21，这是 2023-06-01 之后三年多来的第一次版本换代，七个语言的 SDK 与 ant CLI 同步跳到新大版本，默认发送新版本号：Python 2.0.0、TypeScript 1.0.0、Go 2.0.0、Java 3.0.0、C# 13.0.0、PHP 1.0.0、Ruby 2.0.0。在 Amazon Bedrock 上，2026-10-21 只覆盖 Claude 4.7 及更新的模型，调用旧模型需要留在原版本。

按官方迁移文档，破坏性变更有三处：请求里带 temperature、top_p 或 top_k 一律返回 400，即使填的是默认值，Message Batch 与 token 计数同样受影响；assistant 消息里直接放 document 块报错，需要改放到 user 消息；user 消息里带非空 citations 数组的文本块报错。旧行为没有等价替代，Anthropic 的说法是需要非默认采样的请求可以留在 2023-06-01，该版本未设退役日期。SDK 侧另有三处：密钥改走 Authorization: Bearer，替掉 X-Api-Key，代理与网关若不改会静默拿不到凭证；Python 客户端只接受一个凭证，同时传 api_key 与 auth_token 会抛 ValueError；TypeScript、Go、Java、Ruby 的 SDK 与 CLI 移除了旧版 Text Completions，许可从 MIT 换成 Apache 2.0。Admin API 若干字段改名，例如 API key 的 workspace_id 改为读 scope。

关注理由

对搭 agent 平台与评测流水线的团队，这是一次必须排期的工程迁移。采样参数被移除影响面最广：过去用低 temperature 求稳定的代码路径与新模型的能力取向冲突，只能留在旧版本或接受默认；Bearer 头的改动在中间有网关、日志与测试替身的场景下属于静默失配，排查成本高于报错。Anthropic 未给旧版本退役时间，新旧并存会拉长双版本维护期，早迁移的收益主要在于少维护一套分支。

Anthropic 迁移文档 https://platform.claude.com/docs/en/api/migration-2026-10-21

NO.05 · 具身智能 · 端侧推理

小鹏 IRON 换到第二代 VLA：每 0.2 秒重新推理一次，预判 6 秒内的人类动作

具身智能 端侧部署 人形机器人
事件简述

10 月 22 日，小鹏宣布第二代 VLA 大模型完成升级，在时序理解与未来行为预测上增强，并已端侧部署到人形机器人 IRON。据官方描述，IRON 每 0.2 秒依据眼前画面重新推理一次，预测 6 秒内的动作变化，握手、碰拳、击掌过程中对方临时改招，它能立刻调整姿态或换手配合，不依赖云端遥控。硬件方面，IRON 搭载三颗自研图灵 AI 芯片，总算力 2250 TOPS，具备 VLT、VLA、VLM 组合的大小脑结构。按公司计划，人形机器人 2026 年底实现量产，2027 年上半年开启交付，先落门店与商场等商业场景，再向工业与家庭拓展。

关注理由

人形机器人交互的短板一直落在节奏上：人不会按机器的节拍出招，识别一次手势再执行一套动作的做法，遇到对方中途变招就僵住。把闭环换成持续重推理，等于把响应时间从秒级压进 0.2 秒的量级，代价是模型必须跑在端侧并且算力管够，这也是三颗芯片给出 2250 TOPS 的原因。变量是演示场景集中在近距离手势互动，与产线或家庭里的长时任务不是一个难度；量产与交付时间来自公司口径，尚无第三方验收数据。
