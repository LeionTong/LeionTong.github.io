NO.01 · 具身智能 / AI coding

Artificial Analysis 发布 AA-Robotics v0.1，通用大模型经编程 Agent 操控真实机械臂

具身智能 AI coding 评测
事件简述

10 月 14 日，评测机构 Artificial Analysis 发布 AA-Robotics v0.1：五款前沿模型各控制一台 Hiwonder NexArm 六轴机械臂，围绕倒水、写字、搭积木等八项桌面任务做零样本尝试。模型起初只知道机械臂的名称与 HTTP 控制接口，需自己看摄像头、理解物体位置、编写并运行程序。

综合成绩：GPT-6 Astra 69.4 分居首，GPT-6.1 Sol 64.6、Gemini 4 Argon 55.3、Claude Opus 5.5 48.8、Claude Fable 5.1 46.3。每题满分 100 且允许过程分，Astra 总分最高但八题中仅四题满分，Sol 反而有五题满分。完成一项任务平均约半小时，人工基线约 20 秒；Astra 单项模型调用成本平均 16.36 美元，Sol 仅 1.93 美元。六项抓取任务中Astra 成功率 45%、Fable 5.1 44%、Sol 28%。

关注理由

这是第一次把「通用大模型 + 编程 Agent」直接接到真实机械臂上做体系化量测：模型靠 Codex、Claude Code、Antigravity 这类编程工具读画面、规划动作并下发控制命令，而不是调用专用 VLA 策略。成绩说明语义与空间理解已够用，瓶颈转到速度、成本与接触反馈下的纠错——Astra 与 Sol 约六成时间花在规划，机械臂实际运动只占约一成。对具身智能方向，这既划出了专用 VLA 与运动控制的生存空间，也给「通用模型能否替代机器人大脑」的争论提供了第一组可复现的数字。首批名单暂无中国模型。

NO.02 · AI coding / 具身智能

Gemini 4 Argon 开放付费层，同时公布机器人、代码库与科研结果

AI coding 具身智能 前沿模型
事件简述

10 月 13 日，Google 把 Gemini 4 Argon 开放给 Gemini API 与 Gemini 平台的付费层、Google Antigravity 的 Ultra 订阅，以及 Gemini 应用与搜索的 Ultra / Pro 订阅用户。同日公布的应用结果包括：

仅通过观看视频为 Apptronik 的 Apollo 人形机器人生成训练环境，使其连续命中投沙包 7 次；从一张桌面照片构建物理模拟、生成 4500 多个训练回合，把机器人在真实任务中的成功率从 56% 提升到 75%；在 Google 现有代码库上无人值守工作约 11 小时，把会话准备开销降低约 40%、包导入速度提升 21%；生成一个量子算法组件，时空成本比此前方法低 100 倍以上，并用 Lean 做了形式化验证。优惠期定价为输入每百万 token 2 美元、输出 10 美元。

关注理由

Google 这次把旗舰模型的演示从刷榜挪到了「真实工作流里跑多久、省多少事」：11 小时无人值守改代码属长程 agent 任务，机器人侧则是用模型生成仿真训练数据再迁移到真机，绕开真实数据采集的瓶颈。两条线指向同一件事——前沿模型的价值开始体现在能否持续自主执行、能否补充数据，而不只是单次问答。需要留意这些数字均为 Google 官方口径，且 Argon 在同期 AA-Robotics 机械臂榜单上只列第三。

NO.03 · 终端智能 / AI Agent

豆包手机助手屏幕自动化协议公示结束，155 款应用明确拒绝 AI 代操作

终端智能 AI Agent 生态规则
事件简述

10 月 14 日，字节豆包手机助手的《屏幕自动化操作声明协议》（SAEP）结束 30 天公示期，公布的拒绝清单共 155 款第三方应用（首发 151 款，当日更新）。腾讯旗下 66 款、阿里 23 款、美团 11 款、快手 14 款在列，覆盖微信、QQ、淘宝、天猫、支付宝、饿了么、高德等头部应用；Kimi、DeepSeek 等 AI 同类产品同样拒绝。

规则上，公示期内默认不开放、仅主动声明同意的应用可被操作；公示期后未提交拒绝声明的应用按风险层级逐步开放；已明确拒绝者始终不被自动化操作，开发者可随时调整。该能力基于系统级权限，可在后台读屏与模拟点击，见于 9 月 16 日开售的努比亚 NaviX Ultra。

关注理由

这是移动端 AI 入口权的第一次公开博弈：当 Agent 能替用户跨应用点按屏幕，App 沿用十几年的入口、分发与商业化路径就被绕开，于是大厂选择用协议而非风控弹窗来划线。「未拒绝即默认开放」的机制把决定权推给了应用侧，也把「谁能代表用户操作界面」变成需要生态共同签署的规则问题。对终端智能方向，这说明系统级 Agent 的落地瓶颈已从模型能力转到权限与生态协商。

NO.04 · 前沿模型 / AI coding

Meta 发布首个前沿级模型 Muse Wonder 与 Wonder Full，Muse Code 订阅可调用

前沿模型 AI coding 记忆
事件简述

10 月 12 日，Meta 超级智能实验室发布 Muse Wonder 与 Muse Wonder Full，为 Meta 重组 AI 团队以来首个前沿级模型（内部代号「西瓜」/ Watermelon），在俄亥俄州 Prometheus 数据中心训练。Meta 称其在编程、金融与法律等场景的能力可与 ChatGPT、Claude 同级，内部基准与 Fable 5.1、GPT-6 Astra 相当。

官方强调「主动记忆」，称在 MemoryBench 上得分高于 Fable、Opus 与 Astra。开放方式上，Muse Wonder 通过 Meta Model API 提供，Wonder Full 仅面向 Muse Code 订阅用户、不走 API；两者后续都会用于驱动 Muse 智能体。此前 Muse 系列只推过轻量模型 Muse Spark 与终端编程智能体 Muse Code。

关注理由

Meta 此前长期回避与 OpenAI、Anthropic 正面发布顶级模型，这次把 Wonder Full 只绑在终端编程智能体 Muse Code 上、不单开 API，等于用「模型 + 编程 agent 订阅」的方式直接切开发者入口。把长期记忆当主打卖点，也说明竞争点正从单轮能力转向跨天跨周的任务连续性——这恰是长程 coding agent 的刚需。所宣称的能力水位仍需第三方在使用中检验。

NO.05 · AI Agent / 开发者工具

DeepSeekHarness 面向国内开设官方账号，同期 DeepSeek 服务中断近 5 小时

AI Agent 运行平台 稳定性
事件简述

10 月 15 日上午，DeepSeek 网页与 API（含对话服务、V4 Pro、V4.1 Flash）出现部分中断：故障自北京时间 8:11 起、13:04 恢复，历时约 4 小时 52 分，官方状态页全程更新「已定位原因、正在修复」。

同期，DeepSeek 的开源 Agent 运行平台 DeepSeekHarness 在 B 站开设官方账号，主页尚空但关注量已过万。Harness 定位是为模型提供工具调用、文件编辑、命令执行与多子 Agent 任务拆分的运行层，官方口号为 Everything is a plugin（一切皆插件）。

关注理由

国产模型厂商正在把 Agent 运行层当独立产品运营：Harness 决定模型能否稳定调用工具、跑长任务，是与终端编程工具正面对上的一层，开官方账号意味着从开源项目转向面向国内开发者的产品化推广。服务中断与新产品上线官方未给出关联证据，但「网页与 API 同时中断、又发生在推广动作前后」对依赖其 API 的 agent 工作流是现实风险——把长任务跑在单一模型服务上时，稳定性正在成为与能力同等重要的选型标准。
