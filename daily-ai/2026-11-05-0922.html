NO.01 · 开源权重 · 编程智能体

Ricursive 发布 65B 稠密模型，终端编程基准反超八倍参数的对手

开源权重TerminalBench 2.1稠密架构单机可跑
事件简述

11 月 5 日，Ricursive Intelligence 发布 Ripple-65B Preview 并开放权重。这是一个 65B 参数、80 层的稠密 Transformer，预训练用 12 万亿 token，支持 100 万 token 上下文；官方口径是在 TerminalBench 2.1 上拿到 80.52 分，标为美国开源权重模型当前最好成绩，高于体量大一个量级的 Reflection Beam 501B（80.1）、Meta Muse Spark Open 816B（76.4）、Thinking Machines Inkling 975B（63.8）与 NVIDIA Nemotron 3 Ultra 550B（56.4）。

团队称全流程研发成本 3200 万美元，为上一任开源领先者的十分之一；强化学习只用 140 万 次 rollout 完成爬坡，约为对手的七十分之一，且未采购后训练数据。选择稠密架构而非混合专家，是为了在 NVIDIA 硬件上简化训练与服务，预训练全程维持 40% 的模型浮点利用率，不加自定义算子、不做量化。模型已上 Hugging Face、Together AI、GMI Cloud 与 OpenRouter，官方称窄小参数可让它在 DGX Spark 一类本地设备上运行。

关注理由

小参数稠密模型在终端任务基准上压过八倍参数的混合专家，说明数据配方与训练配方能在特定能力上抵消规模优势；能落到单机运行，对离线的编码代理直接可用。

分数全部自报，TerminalBench 2.1 只覆盖终端命令一类任务，通用推理与长程项目的表现要等第三方复测；「十分之一成本」的对比口径也由团队自算，复现之前只算一个可验证的候选。

Ricursive Intelligence 官方 https://www.ricursive.com/ripple ；Hacker News https://news.ycombinator.com/item?id=50369925

NO.02 · 模型发布 · 电脑操作

腾讯发布 Hy4，首次支持命令行与图形界面的电脑操作

模型发布Computer Use视觉理解权重待开放
事件简述

11 月 4 日，腾讯混元发布新一代大语言模型 Hy4，相对 8 月的 Hy4 preview 扩大了预训练与后训练数据规模，首次引入视觉理解，并首次支持电脑操作，结合命令行与图形界面处理任务，另对 Blender、CAD 与跨应用长程任务做了专项训练。权重将于近期开放，先发系统卡片。

官方给出的数字集中在办公与金融：WorkBuddy 场景平均得分 83.18、通过率 96.15%；579 项真实金融任务众测得分 3.04，为开源模型最高，对比 Kimi K3.1 Pro 2.68、GLM-5.3 2.68、DeepSeek-V4.1-Flash-1017 2.97；自建测试里幻觉率从 preview 的 12.95% 降到 7.2%，猜测导致的错误率从 23.1% 降到 5.6%，游戏开发评测提升 19.1%。定价不涨，输入 6 元、输出 18 元每百万 token，Hy4 Flash 近期发布。

关注理由

电脑操作能力让模型从生成文本跨到操作软件，配合企业微信套件打通聊天、邮件、日程，是国产模型里少见的模型与办公产品同批迭代的路线；幻觉率下降是这类场景能否交付的前提。

评测多为内部口径与专家众测，权重尚未实际放出，终端操作在真实软件上的成功率、误操作代价都还缺公开数据。

美通社（腾讯）https://www.prnewswire.com/apac/zh/news-releases/-hy4-302929174.html ；Hacker News https://news.ycombinator.com/item?id=50365780

NO.03 · 代码基建 · 收购

OpenAI 收购 Pierre，把 Codex 用的 diff 与代码存储工具收进自身体系

收购版本控制Codex待监管批准
事件简述

11 月 4 日，OpenAI 宣布收购 Pierre Computer Company，即 Code Storage 服务与 Trees、Diffs、Highlights 等开源开发工具的开发者。Codex 客户端的文件浏览与改动审查用的正是 Trees 与 Diffs；Diffs 的编辑模式可在审查处直接改代码，Highlights 是随输入实时更新的语法高亮。交易尚待监管批准，两家在交割前保持独立。

OpenAI 同期公开了内部 Git 后端 Pando，说明当代码改动大量并行产生时，Git 周边的系统要跟着改。官方表态是让 Codex 承接从第一条分支到部署的全流程，Pierre 的开源项目继续开源并继续贡献；Code Storage 在交割后仍可使用，功能将并入 Codex。

关注理由

编码代理的瓶颈已经从生成代码挪到并行分支、审查与仓库吞吐，把版本控制这一层收进自身体系，等于掌握了代理产出流入主干的那道闸门。

对依赖 Git 托管与审查流程做工具的一方，上游被垂直整合是直接冲击；开源项目承诺继续开源也只到口头层面，改许可证与改接口都随时可能发生。

NO.04 · 推理验证 · 密码学

Anthropic 用零知识证明验证模型身份，单张 H100 每秒出 110 个 token 的证明

推理验证zkSNARK独立评测Apache 2.0
事件简述

11 月 4 日，Anthropic 前沿红队公布 FlashProve 的进展：用 zkSNARK 为推理过程生成密码学证明，让用户在不知道权重的情况下核验某段回答确实出自指定模型，且证明本身不暴露权重。测试模型为 Llama 4 Maverick（400B 混合专家，第三方 4bit 量化），单张 H100 生成速度约 110 token/秒，1024 token 请求的证明约 19MB，GPU 时间是 vLLM 直接推理的 70 到 95 倍，比既有开源系统快几个数量级。

团队同时放出技术报告、协议说明、C++ 快速验证器，以及用 Lean 写成的可证明正确验证器与顶层数学命题证明，代码与证明以 Apache 2.0 公开。当前系统只能覆盖 1024 token 的上下文，隐藏的是权重而非架构，官方定位为中间进展。

关注理由

要解决的问题是路由服务按成本偷换模型、token 流被中途篡改时光看输出判断不出来；对独立评测机构、合规审计与「按声明模型交付」的商业约定，这是基础设施而不是学术趣味。

两个数量级的开销与 1024 token 的上限，意味着它现在只适合校验单次问答，离长会话与代理轨迹还差很远；隐藏权重不隐藏架构，也留了信息面。

Anthropic 研究 https://www.anthropic.com/research/provable-inference ；Hacker News https://news.ycombinator.com/item?id=50368626

NO.05 · 具身智能 · 推理模型

招商局狮子山开源 35B 具身推理模型，激活 3B 在十项基准全线上涨

具身推理MoE 3B 激活能力蓝图开放权重
事件简述

11 月 4 日，招商局先进技术研究院下属狮子山人工智能实验室发布具身推理视觉语言模型「驭物」Lion-ER-35B-A3B，混合专家架构、总参数约 35B、每 token 只激活约 3B。十项公开具身基准以 avg@4 口径评比，等权综合均分 65.29，全部高于所用基座：Where2Place 64.28（提升 9.30）、ERQA 64.38（提升 6.19）、SAT 89.33。权重已在 Hugging Face 以 BF16 格式开源，兼容 Transformers、vLLM、SGLang。

方法上不追加数据量，而是先列出 8 个一级领域、39 项二级能力的能力蓝图，把 31.2 万条监督样本按能力预算分配权重，再用评测找短板，从 31 个数据源、约 430 万条素材里定向补同逻辑不同场景的题目。公开案例集中在相机转向判断、轨迹可达性、跨视角空间映射与任务步骤是否完成。

关注理由

模型检验的都是语言指令落到物理动作时的断点：分不清物体在动还是相机在动、挑出一条碰不到目标的轨迹、把「正在靠近」当成「已经到位」，这些错的代价直接是撞机与错序。

把评测当下一轮数据生产起点，比堆数据可复用；但十项基准是自选组合，评测集与训练能力蓝图同源，仍要靠外部在不同本体上跑一遍才算数。

量子位 https://www.qbitai.com/2026/11/507586.html

待跟踪

  1. Ripple-65B 在 TerminalBench 之外的独立复测，以及稠密 65B 在真实仓库里的长程稳定性。
  2. Hy4 权重实际放出的时间与许可证，电脑操作在非腾讯系软件上的成功率与误操作恢复。
  3. Pierre 交割后的开源项目是否改许可证，Code Storage 并入 Codex 后对外是否还开放。
  4. FlashProve 的上下文长度能否从 1024 token 扩到会话级，证明体积与验证耗时是否可降到消费级。
  5. Lion-ER 在其他厂商本体与真实工位上的迁移效果，能力蓝图的评测集何时公开。
