NO.01 · AI coding · 模型发布

OpenAI 发布 GPT-6.1 Terra，把电脑操作与视觉理解压到十分之一单价

AI coding视觉理解电脑操作API 定价
事件简述

美东 10 月 26 日，OpenAI 发布 GPT-6.1 Terra，定位是低成本承担整天办公与电脑操作任务的中间档模型，能力覆盖屏幕内容理解、跨应用操作与自然语言写作。标准 API 定价为每百万输入 token 1 美元、缓存输入 0.05 美元、输出 5 美元，比 GPT-5.6 Terra 与 GPT-6.1 Sol 低 50%，缓存输入较前代下降 75%。模型支持最多 100 万输入 token，接受文本与图像输入。

官方给出的数据：在测量 agent 使用软件完成专业任务的 Agents' Last Exam 上，中等推理强度较 GPT-5.6 Terra 高 15 个百分点，任务成本约为前代三分之一；最高推理强度下 token 效率是 Claude Opus 5.5 的三倍以上、单价为其四分之一，折算每任务成本约九分之一。命令行任务 Terminal-Bench 4.0 最高推理强度解出 50.3%，前代公布成绩是 21.5%。内部错误诱导提示上的错误率从低推理强度的 53.6% 降到 16.7%，最高强度为 4.3%。

同日在 Amazon Bedrock 与 Microsoft Foundry 上架，ChatGPT Work 与 Codex 的 Plus、Pro、Enterprise、Edu 用户可用，开发者通过 API 名 gpt-6.1-terra 调用。官方在发布说明里提示，最复杂的编码与科研任务仍应选 GPT-6.1 Sol 或 GPT-6 Astra。

关注理由

把电脑操作与视觉理解放到十分之一的单价档，改变的是企业侧高频自动化的成本结构：读发票、填表、跨应用取数这类任务此前卡在单次成本上。Terminal-Bench 4.0 从 21.5% 到 50.3% 说明中间档模型在命令行 agent 上已经越过可用线，很多任务不需要动旗舰模型。

能力分层仍然存在，官方自己把最难的编码与科研任务留给了 Sol 与 Astra。价格与效率数字来自厂商公布与 Artificial Analysis 的折算，没有第三方复现整套评估，缓存命中率对实际账单的影响也需要按自家流量结构算。

NO.02 · AI coding · 代码托管

Entire 上线，用 agent 打分的 Trails 取代 pull request

AI coding代码评审分布式 Git会话记忆
事件简述

10 月 26 日，前 GitHub CEO Thomas Dohmke 创办的 Entire 全面开放，做的是给 agent 与人类协作用的 Git forge。核心是 Trails：代码推送到 Trails 后，评审 agent 在各自独立的云沙箱里跑一遍、提交分数与理由，默认 agent 覆盖代码质量、安全与 slop 三类，页面顶部展示当前一轮与最近五轮的评分。agent 还能返回分等级的 findings 与修改建议，配合按仓库开启的 Gates 要求人工批准与 CI 通过才允许合并。

底层是自建的分布式 Git 服务器，兼容 Git，仓库可跨区域复制，美国、欧盟、澳大利亚、印度已上线。官方基准 ForgeMark 称单个仓库每小时处理约 57 万次 clone、每秒 586 次 push，比 GitHub 快最多 89 倍、比 Cursor Origin 快 6 倍。另一块 Continuous Memory 把 agent 会话与提示词同步进仓库，供后续检索。评审跑在 Daytona 与 E2B 的隔离沙箱上，模型侧用 Claude Code 与 Codex，CI 合作方是 Buildkite 与 Depot。目前支持私有仓库托管，公开仓库与自托管节点在路线图上。

关注理由

agent 写代码之后，人的瓶颈从写变成了读 diff 与排队合并，Trails 把判断依据换成每轮推送的评分与收敛趋势，让评审退回到看分数决定是否继续迭代。把会话与提示词存进仓库、让下一轮 agent 接着用，指向的是记忆层被一并纳入代码托管。

评分转绿即可合并的边界条件需要谨慎设定，安全类考评能否覆盖业务逻辑错误尚无公开证据；89 倍与吞吐量数字来自厂商自己的基准，独立验证还没有出现。整个平台当前只托管私有仓库，生态与集成深度是长期变量。

NO.03 · 终端智能 · agent 工具

Google 放出 gemini-api，给已有编码 agent 调用 Gemini 的无状态 CLI

终端智能CLI多模态托管 agent
事件简述

Google 在 google-gemini/gemini-api-cli 发布 gemini-api，Apache 2.0 许可，单个 Go 二进制，覆盖 macOS、Linux 与 Windows。定位是把 Gemini 的能力交给用户已经在用的 agent：把 gemini-api 放进 PATH 并配好 API key，Claude Code、Codex、Cursor、Antigravity、OpenClaw 等带 shell 权限的 agent 就能生成图像、视频、语音与音乐，分析 PDF、图像、音频、视频与 YouTube 链接，把录音转写成 md、json 或 srt，或在后台起一个托管 agent 并保留 interaction ID 取回结果。

工具本身无状态、无会话记忆、无聊天模式，上下文与计划由宿主 agent 掌握，每次调用独立执行。命令树、参数、请求 schema 与用法内建在二进制里，agent 可用 --help、--usage、--schema 自行发现接口，--dry-run 只校验参数并打印脱敏后的请求而不发网络调用，--agent-mode 让 stdout 默认输出紧凑 TOON、stderr 输出结构化 JSON 错误。默认模型覆盖 gemini-3.8-flash、gemini-nano-banana-2.1、lyria-3.5、gemini-omni-1.1-flash 等，另有 environments、credentials、webhooks、triggers 等托管 agent 相关子命令。项目标注为 beta，仓库建于 2026 年 4 月，目前不接受外部 PR。

关注理由

把多模态与托管 agent 做成无状态 shell 命令，等于把自家模型能力作为一组可组合工具交给别人家的 harness 使用，宿主 agent 自己管上下文与计划，凭据与权限边界留在宿主一侧。对做编码 agent 的团队，图像、语音、转写与后台研究这些旁路能力不必各接一遍 SDK。

无状态意味着多轮状态得由宿主用 interaction ID 自己串，长任务的会话管理仍在宿主这边。默认模型版本随仓库演进，且项目处于 beta，CI 与自动化流程里应钉住具体 release。是否接受外部贡献未开放，工具演进节奏由 Google 单方决定。

GitHub https://github.com/google-gemini/gemini-api-cli ；Google AI for Developers https://ai.google.dev/gemini-api/docs ；Google AI Studio https://aistudio.google.com/learn

NO.04 · AI coding · 开放权重

月之暗面发布 Kimi K3.1 Pro，2.8T 开放权重模型贴近 Opus 5.5 的终端成绩

AI codingMoETerminal-Bench开放权重
事件简述

10 月 23 日，月之暗面发布 Kimi K3.1 Pro，K3.1 系列首个模型，由 Kimi K3 后训练而来，在数百个下游领域做联合强化学习。规格为总参数 2.8T、每 token 激活 104B 的 MoE，100 万 token 上下文，API 接受文本、图像与视频输入，思考默认开启，推理力度分低、高、最高三档。同发 Highspeed 版，官方称质量一致而速度提升 2 到 3 倍。

官方自评：Terminal-Bench 4.0 为 65.7%，对照 Claude Opus 5.5 的 66.4% 与 GPT-6 Astra 的 58.2%；SWE-Marathon 51.7 领先 Opus 5.5 的 46.3；BenchCAD 带工具 92.7%；内部基准 Kimi Hallu Bench Hard 的声称级幻觉率从 K3 的 23.4% 降到 8.3%。偏低的分项同样明确，Terminal-Bench Science 0.1 为 38.1，对照 GPT-6 Astra 的 68.1。定价为每百万输入 2 美元、输出 10 美元，缓存输入更低，已上线 Kimi.ai、Kimi Work、Kimi Code 与 API，完整权重承诺 11 月 4 日前放出。第三方方面，Artificial Analysis 的 Intelligence Index 给出 55 分，较 K3 提升 11 分，位于 Opus 5.5 的 58、Sonnet 5.5 与 Muse Wonder Full 的 56 之后。

关注理由

把 3T 级模型承诺开放权重，等于把可自托管的编码 agent 基座再往前推一档：终端任务上贴着 Opus 5.5、压过 GPT-6 Astra，说明开放权重与闭源的差距在命令行场景里继续收窄。缓存的定价分层与 100 万上下文，也把长程编码任务的单次成本预期往下拉。

自评分数多数跑在 Claude Code harness 上，换 harness 会有几个点的浮动；官方自己的科研类分项明显落后，说明长尾任务能力还不齐。权重尚未落地，2.8T 总参数对应的显存与推理成本要等放出后才能评估，能否在自有硬件上跑起来是关键未知数。

NO.05 · AI Agent · 安全边界

Downloads 里的一份 AGENTS.md 可以劫持 Codex 与 Claude Code

AI Agent提示注入沙箱供应链
事件简述

安全公司 Forever Security 在 10 月 22 日发布报告《Markdown Is the New Executable》。事件起因是一位客户的机器上，~/Downloads 里出现一份约 13KB、伪装成工程笔记的 AGENTS.md，末尾一段要求编码 agent 安装已知恶意的 npm 包 function-color，该公司的监控在代码执行前拦下了这次安装，文件的来源未能查明。

研究者在虚拟机中复现了这条路径：浏览器可以把文件不经点击写进 Downloads（Chrome、Edge、Firefox 默认如此，只弹下载提示），而编码 agent 会读取并执行启动目录里的指令文件。针对 Codex，伪造文件令其向全局配置 ~/.codex/config.toml 添加 MCP server 条目，在超过 90% 的尝试中执行了载荷；针对 Claude Code，一份伪造的 CLAUDE.md 让项目设置改指研究者的网关，约 50% 的测试里会话 OAuth token 被一并送出并导致代码执行，其中约五分之一通过子代理在同一会话内执行。报告中提到约半数客户曾把编码 agent 放在 Downloads 目录里启动。function-color 与 MALFEX 活动相关，10 月 7 日已被替换为安全占位包。

关注理由

攻击落在 agent 的信任模型与浏览器下载默认值的交叉处：agent 信任启动目录里的指令文件，浏览器默认把抓到的文件写进同一个目录，两家厂商都没有可直接打的补丁，暴露面取决于 agent 从哪里启动。这解释了为什么目录级信任提示与沙箱无法被指令文件替代。

对把编码 agent 接进日常流程的团队，可执行的边界是把 agent 只从自己创建或检查过的项目目录启动，AGENTS.md 与 CLAUDE.md 要先当代码读一遍再用，并定期检查 Codex 的 config.toml 与 Claude Code 的 settings.json 里有没有陌生的服务端或 API 地址。发现植入文件后应按 token 已泄露处理并轮换凭据。
