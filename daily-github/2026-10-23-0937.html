OpenShell NVIDIA/OpenShell

⭐ 17,815 · 近 30 天未获取到 Rust · Apache-2.0 最近提交 10-23 · v0.1.5（10-20）

定位跑自主 agent 群的沙箱运行时，用内核级隔离加一份声明式 YAML 策略，划清能读的文件、能连的网络与能用的凭据。

痛点agent 要读文件、装包、调接口才有用，给足权限又等于把源码与密钥摊开；托管沙箱按台按月收费，上下文还得过第三方。

付费代码 Apache-2.0；付费位置在企业侧的支持与合规，私有模型端点、策略审计与策略证明都归到厂商的企业线。

规模化凡让 agent 碰生产数据的团队都要这一层，策略文件可版本化复用，换行业不改产品。

边际成本低 · 纯软件，跑在客户自己的机器上。

验证curl -LsSf https://raw.githubusercontent.com/NVIDIA/OpenShell/main/install.sh | sh，然后 openshell sandbox create --name demo，默认镜像是干净的 Ubuntu，装 agent 的步骤见官方 Run Your First Agent。

风险564 个 open issue，版本仍在 0.1.x；需要 Linux、Apple Silicon 或 WSL 2 加 Docker 或 Podman；策略代理与形式化证明对运维是新概念，规则配严了 agent 直接干不了活。

HyperFrames heygen-com/hyperframes

⭐ 70,032 · 近 30 天未获取到 TypeScript · Apache-2.0 最近提交 10-23 · v0.8.186（10-22）

定位把 HTML、CSS 与可定位动画渲成确定性 MP4 的开源框架，配 CLI、Studio 桌面应用与给编码 agent 用的 skill。

痛点批量做产品介绍与数据动画，要么买按量计费的生成服务，要么手搓时间线；模型现写的一段代码往往渲不出稳定帧。

付费本地渲染免费，且不消耗 HeyGen 额度；收费落在托管创作流程、语音、数字人与生成媒体上，接厂商既有订阅。

规模化营销、产品、教程视频是同一套模板化产能，项目结构能被 agent 批量复用。

边际成本中 · 引擎免费，但托管渲染要占 GPU 算力，成本随渲染分钟数走。

验证npx skills add heygen-com/hyperframes 选 Core Skills，再让 agent 生成一个十秒短片；手写路径是 npx hyperframes render --output video.mp4。

风险405 个 open issue，Windows 桌面版尚未发布；渲染时长跟动画复杂度强相关，做到长片要排机器；叠加外部语音或数字人服务时费用另算。

Cloudroom core davidondrej/cloudroom-core

⭐ 982 · 近 30 天未获取到 Rust · Apache-2.0 最近提交 10-22 · core-v0.1.72（10-22）

定位把 Claude Code、Codex、Pi 这类编码 agent 放到自己 Linux 机器上跑的 Rust 服务，每个 agent 一个沙箱、各占一条 Git 分支，会话历史留在本机。

痛点笔记本合盖 agent 就停，本地并行开几个 agent 互相踩文件；托管方案按月按 agent 计费，代码与密钥要过第三方。

付费价目公开：Free 每 30 天 100 个云端 agent，Pro 每月 50 美元、Super 150、Ultra 500；模型订阅自备，核心自托管免费，托管版当前邀请制。

规模化从一人一机到团队多机是同一套安装脚本，agent 换 harness 不改核心结构。

边际成本中 · 每个 agent 独占一台沙箱，算力是真实成本；交付只发二进制与安装脚本。

验证在全新的 Ubuntu 24.04 上 curl -fsSL https://raw.githubusercontent.com/davidondrej/cloudroom-core/main/install/install.sh -o install.sh 后 sudo bash install.sh，脚本校验下载、建账号、写 token 并起服务。

风险开发者 alpha，2026-09-17 建库、只有 982 星、6 个 open issue；agent 默认不带审批提示，官方要求一机一可信用户；仅支持 Ubuntu 24.04 与 Apple Silicon 桌面端。

MailCheap marclou/mailcheap

⭐ 1,307 · 近 30 天未获取到 JavaScript · AGPL-3.0 最近提交 10-21 · 无 release

定位按发送量计费的播报应用，写作、发送、站点发布与统计在一套界面里，也能整条流程由 agent 经 MCP 与 REST 调用。

痛点多数工具按订阅人数收费，作者为几个月不打开邮件的人继续付钱；想保住送达率还得手动清理名单。

组合观察

五个项目的收费位置同时从按席位、按订阅人数挪到按用量：沙箱按云端 agent 计、回归网关按 trace 计、播报按发送量计、渲染引擎按托管分钟数计，引擎本身免费送出去当入口。对买方，账单会从「多少人用」变成「用了多少」；对卖方，毛利取决于单个 agent、单条轨迹、单封邮件与每分钟渲染的成本能不能压到订阅制之下。
