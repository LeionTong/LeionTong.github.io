显卡的空闲时段正在被切开计价。Beam 的沙箱标到 0.06 美元每小时，H100 一块卡 1.83 美元每小时；Pixeltable 的托管按 0.035 美元每 vCPU 每小时收；GPUStack 直接把配额、限流与计量做进企业版。这些价格成立的前提，是底下有一整套东西撑着：谁来调度显卡、缓存放在哪、不可信的代码在哪执行、多模态数据存成什么样。

GPUStack gpustack/gpustack

⭐ 6,064 · 近 30 天未获取到 Python · Apache-2.0 最近提交 2026-11-17 · v2.3.1（11-11）

定位把机房、Kubernetes 集群与公有云上的显卡收成一个资源池，替人配好 vLLM、SGLang、TensorRT-LLM 这类引擎，也能按需开出带 SSH 的显卡实例。

痛点显卡型号混杂、各家引擎参数不同，部署一个新模型要重调一遍显存切分与并行配置，运维侧没有统一入口。

付费官网单列 GPUStack Enterprise，含显卡调度、配额与限流、计费与用量统计；一套平台可以按卖 token（MaaS）和卖显卡时长（GPUaaS）两种形态收费，具体报价走销售。

规模化原生支持 NVIDIA、AMD、昇腾、海光、摩尔线程等加速卡，自建机房与混合云共用一套控制面，换硬件不用换平台。

边际低 · 纯软件，Docker 或 Helm 交付，显卡由客户自己采购。

验证一条命令起服务，登录 80 端口后添加一个模型即可对话：

sudo docker run -d --name gpustack --restart unless-stopped -p 80:80 \
    --volume gpustack-data:/var/lib/gpustack gpustack/gpustack
风险worker 节点只支持 Linux，Windows 需走 WSL2 且官方不建议 Docker Desktop；企业版的计价方式没有公开，要谈；显存切分依赖具体驱动与固件版本，偶发识别不到显卡。

Mooncake kvcache-ai/Mooncake

⭐ 7,062 · 近 30 天未获取到 C++ · Apache-2.0 最近提交 2026-11-17 · v0.3.14（11-03）

定位Kimi 背后的 KVCache 分离式推理架构：预填充与解码分到不同机器上跑，缓存单独成层，靠传输引擎在节点之间搬运。

痛点多轮对话与长上下文反复重算前缀，显卡花在等缓存搬运上的时间比花在计算上的还多，单机显存也装不下热门前缀。

付费项目本身不直销。做 MaaS 与私有化推理的团队拿它压低单 token 成本，价值体现在同一批显卡的吞吐与首字延迟上；FAST25 论文与线上真实 trace 都已公开，评估有据可查。

规模化传输引擎已覆盖 NVIDIA、昇腾、AMD、寒武纪、摩尔线程等后端，跨机房与云上网络都能接入。

边际中 · 软件免费，收益依赖 RDMA 与高速网络，交付时要按集群规模调参。

验证装好传输引擎，按文档的 quick-start 在单机起 Store 与 Transfer Engine，跑一次缓存搬运确认链路通：

pip install mooncake-transfer-engine
风险拿到全部收益需要八块显卡以上的集群与 RDMA 网络；KV 缓存与分离式调度里有一部分不在开源核心内，要自己补齐；版本号仍在 0.3，接口会动。

beta9 beam-cloud/beta9

⭐ 1,855 · 近 30 天未获取到 Go · AGPL-3.0 最近提交 2026-11-18 · worker 与 gateway 每日发版

定位自建的无服务器运行时，容器冷启动压到一秒以内，既能接住模型生成的代码沙箱，也能起常驻的推理端点。

痛点智能体要执行不可信的代码，整台虚拟机太慢太贵，进程隔离又拦不住越权，中间这一层长期自己搭。

付费官方云明码标价：沙箱与虚拟机 0.06 美元每小时起，H100 1.83 美元每小时，另有 BYOC 模式把运行时装进客户自己的集群。

规模化沙箱、批处理、推理端点三类负载共用一套接口，接的是标准容器镜像，不绑定具体模型。

边际中 · 卖的是显卡与运行时长，每多一个客户就多一份真实硬件开销。

验证装上客户端，注册后跑文档里的沙箱示例，三十秒内拿到返回值：

pip install beam-client
风险AGPL-3.0，对外提供托管服务前要逐条看清条款；自托管要自备 Kubernetes 与显卡节点；worker 与 gateway 分开走版本号，追版比较费神。

Pixeltable pixeltable/pixeltable

⭐ 1,664 · 近 30 天未获取到 Python · Apache-2.0 最近提交 2026-11-18 · v0.7.24（11-07）

定位多模态数据表、模型计算与 HTTP 服务写在同一个 Python 文件里，图片、视频与嵌入结果落在同一张可查询的表上。

痛点智能体后端通常要拼向量库、对象存储与任务队列三套系统，新增一种模态就要重写一遍处理管道。

付费Community 版免费但空闲七天会停机；Pro 版 29 美元每月外加 0.035 美元每 vCPU 每小时；企业版可做单租户 VPC 与 BYOC；自托管 Apache-2.0 永久免费。

规模化视频检索、文档解析、影像标注共用同一套表结构，交付物是一份 app.py，本地与云端同一份代码。

边际低 · 纯软件加托管按量计费，没有硬件依赖。

验证照十分钟教程在 app.py 里声明一张视频表、一个计算列与一条 HTTP 路由，起服务后用 curl 查一次：

pip install -U 'pixeltable[serve]'
风险生态还小，1,664 star，第三方教程少；托管按 vCPU 与存储计费，多模态大文件容易把账单堆高；0.7.x 的接口仍有调整。

kvcached ovg-project/kvcached

⭐ 2,049 · 近 30 天未获取到 Python · Apache-2.0 最近提交 2026-11-17 · v0.1.6（10-03）

定位给显存里的 KVCache 加一层虚拟内存：先占虚拟地址，用到时才映射物理显存，多个模型因此能共享同一块显卡。

痛点一块显卡只跑一个模型时显存大量闲置，跑多个模型又要按峰值预留，切多少、留多少只能人工拍板。

付费项目本身不收费。Red Hat 的 Sardeenz 已经基于它做动态多模型服务，商业价值由集成方在 OpenShift 一侧收取。

规模化支持 SGLang 与 vLLM 两类引擎，AMD 的 ROCm 后端已接，单机与 Kubernetes 都能用。

边际低 · 纯 Python 库，随引擎启动加载，不增加额外服务。

验证装好后打开两个环境变量，起一个 vLLM 实例，对比显存占用曲线：

pip install kvcached --no-build-isolation
export ENABLE_KVCACHED=true KVCACHED_AUTOPATCH=1
风险版本号还在 0.1.x，与引擎版本强绑定（当前对 vLLM v0.30、SGLang v0.5.20）；收益只在多模型共卡时出现，单模型场景没有意义；改的是引擎的内存加载方式，出问题要读源码。

今日首选

GPUStack（gpustack/gpustack）。切分显卡、配置推理引擎、按用量出账这三件事被放进一套可以自托管的软件里，企业版已经把配额、限流与计量做成了模块，卖 token 与卖显卡时长的供应商都能直接挂上去。开源版一条 docker 命令就能验，判断成本很低。

组合观察

集群编排、缓存传输、沙箱执行、数据后端、单卡共享，五个位置拼起来就是一套自建的服务端底座。收费方式都在往时长与用量上靠：Beam 按秒标价，Pixeltable 按 vCPU 小时，GPUStack 把计量做进企业版。自建这一侧的采购对象也跟着变化，一套能自己出账的系统，正在取代单买软件授权的做法。
